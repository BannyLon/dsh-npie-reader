## 订阅与信息源

### 个人订阅

RSS 2.0 / Atom / RDF 订阅，最多 100 个；可从探索目录里挑，也可直接粘贴任意地址（支持一次粘一批，一行一个）；分组、改名、换地址、单源刷新、失败留痕

### 补全历史

**feed 只有最新 N 条时，去站点自己的目录把旧文章捞回来**。订阅行右侧的「补全历史」：先探测并报数（找到多少 / 新增多少 / 前 5 条样例），确认后才写盘。来源按可靠性依次是**归档页 HTML → `sitemap.xml` → `llms.txt`**（后者的摘要会用来补前两者的空摘要）。实测 `lex.qiaomu.ai`：feed 只有 20 条，归档页 506 条，两次请求补全。

- **只补「还没有的」**：按归一化 URL 去重，已有条目的正文/摘要/阅读状态/收藏一条不动；
- **正文不预存**：补进来的条目只带标题+日期+摘要，打开时才抓原文（506 篇 × 50 KB 全存进去会把 `data.json` 撑爆）；
- **上限按源放宽**：补全过的源 `maxEntries` 提到 1000，其它订阅仍是 200 条，存储行为不变；
- 归档页解析不到 5 条就**不认**（避免把导航页当成文章灌进来）；
- **入口按条件出现**（`canBackfill()`）：条数 < 100、没补过、**没查过** —— 查过确认「没有更多」后按钮当场收起，不会永远挂在每一行上；**站点明确回 404 才算查清**，超时/断网不记标记（网络抖一次不该让功能消失）。行内三个图标按钮都有**悬停提示**（两行：动作名 + 一句说明），提示用 `position: fixed`，不会被订阅列表的滚动容器裁掉

### 频道

侧栏顶部的频道按钮在「全部 / 我的订阅 / 分组 / 单个源」之间切换；新增订阅后会自动回到「我的订阅」，让所有源的文章同屏。

- **侧栏有宽度下限 256px，被挤窄时既不裁也不换行**（0.45.2）：下限写成一个 CSS 变量 `--npr-sidebar-min`，两条列宽公式（宽面板的基础规则、窄面板的 `clamp(var(--npr-sidebar-min),42cqw,300px)`）与 JS 的拖动夹取、首屏读回 `npr.listWidth` 都用它。256 是**量出来的**：工具栏不溢出要 240（三档视图 88 + 四颗图标 4×28 + 内边距 20 + 间距 10；0.60.0 又添了一颗「澄境阅读助手」，`npm run verify:layout` 复跑仍全绿，240 这个数没变 —— 但再加第六颗就得重新量），四颗 chip 单行要 244，两位数计数「已隐藏 12」要 252 —— 0.45.1 曾把下限设成 232，那只够「不溢出」、不够「不换行」，用户 2026-10-29 的原话是「换行显得非常的业余，而且顶上的工具条也被遮挡」。
- **为什么不给 `.npr-sidebar` 加 `container-type` 去量它自己**：那样它内部**所有无名**的 `@container (max-width:700px)` 规则会改按侧栏宽度求值，而那些规则本来是量**面板**的（全项目 10+ 条断点都靠无名查询），会集体误触发 —— 这是这里最直觉也最危险的解法。判据是**真 Chrome 七档面板宽**（460/500/560/620/700/900/1200）同时量五件事：不低于下限、三行都不横向溢出、没有子元素右缘越界、**筛选条只有一行**、每颗 chip 的文字没被裁 —— 只量 `scrollWidth` 分不出「换个排法」和「把字裁掉」，而「换行」是第三种坏法

### 源新鲜度

每个源标出「今天有更新 / 最新一篇 N 天前 / 已 N 天未更新」，陈旧源整行淡化；打开陈旧源时提示可换地址 —— 第三方源会悄悄停更，界面不能装作没看见

### 自定义信息源

内置目录之外的地址，**把地址粘到探索页的搜索框**即可订阅（支持一次粘一批，一行一个）。内置的只能隐藏（内置目录要能跟插件升级更新），页脚可一键恢复

### 转 RSS 服务

设置页 → 订阅管理里的「转 RSS 服务」：填一个自己搭的转 RSS 服务地址（如 wewe-rss）后存下来，可**保存并检测**连通性 —— 会区分「连不上 / 返回的是网页（正常，去后台加号）/ 地址本身就是 feed / 是接口不是 feed」，并写明「实时在公众号上不存在」。**插件不代转**：转 RSS 需要登录态与浏览器自动化，必须由你自己的服务完成

### 探索目录

内置订阅目录：**Newsletter 18** / 独立博客 404（2026-10-08 按实测裁剪，原 1415 → 404）。**「精选作者 / 微信公众号 / 播客」三类已摘除** —— 它们的数据来源说不清楚，详见下方「边界与已知限制」。**两类都进体检**：每行标出结论（最新一篇 N 天前 / 已 N 天未更新 / 上次体检没抓到），分类下方常驻一行**来源说明**，页脚带体检日期。筛选条上另有一排**订阅分组选项卡**（与目录分类并列；点分组只列出该组下的已订阅源），宽度放不下时折叠成「···」，点开可选到被折叠的分组；**与目录分类同名的分组不单独出标签**，直接并进那个分类 —— 你自己的那批源排在最前面（标「我的订阅」），目录里还没订阅的接在后面（订阅时本就按分类建组，`Newsletter` 只会有一个）。「**全部主题**」下拉只列**至少 3 个源在用**的标签、**按使用次数降序**（386 → 65），大小写不同的写法合并成一项；当前分类没有标签时（Newsletter 那 18 条都没有 tags）整个下拉禁用

### 平台链接订阅（0.84.0）

**粘 Apple Podcasts / 小宇宙 / YouTube 的节目链接就能订阅**，不用自己去页面源码里翻 feed。分两层：`src/feed-platform.js`（纯函数，两端共用同一套分类与挖掘规则）+ `src/host/feed-resolve.js`（抓取靠注入，假响应能真跑一遍）。

- **三条腿的可靠性差很多，所以每条各说各的**：**Apple 最稳** —— 从 `podcasts.apple.com/…/id1493503146` 取出 collectionId，`itunes.apple.com/lookup?id=…&entity=podcast` 直接回 `feedUrl`（实测 161 ms）；**小宇宙不公开 RSS** —— 只能读页面 `__NEXT_DATA__` 拿节目名，再去 Apple **中国区**目录 `search?term=…&entity=podcast&country=cn` 反查（实测 752 ms，冷缓存 2913 ms）；**YouTube 只能拿到频道 feed** —— 频道页里挖 `channelId`（canonical / `"channelId":"UC…"` / `channel_id=` 三种写法都认）→ `feeds/videos.xml?channel_id=…`。
- **小宇宙页面裸 `fetch` 回 403**（实测），必须带浏览器 UA ⇒ 抓 HTML 与抓 feed 是两条路（`fetchHtml` / `fetchText`），不共用。
- **任意网页**也认：读 `<link rel="alternate" type="application/rss+xml">`（RSS 优先于 Atom），`ruanyifeng.com/blog/` → `feeds.feedburner.com/ruanyifeng`，实测 1272 ms。
- **失败分得出「打不开」与「没有」**：苹果三个区全连不通报「目录连不上」，连得上但查不到报「目录里没找到这个节目」—— 合成一句「解析失败」，用户只会一直重试同一个链接。
- **输入框 500 ms 去抖预解析**，先用一行小字写「会订阅到 <feed>（标题）」，确认后才真订阅；直接是 feed 地址或普通网页时**不预解析**（本来就能订，多一次请求只是慢）

### 全文抓取

订阅源只给摘要时，去原文页抽取正文；可在设置里关闭，也可对单篇强制抓取

### AI 伴读

把当前文章（或选中段落）作为引用材料带进 Harness 原生对话追问。**电子书也能伴读**：右侧面板把**当前页的文字**带进同一套 Harness 原生对话，翻页即同步 —— PDF 取**文字层**（没有就本机 OCR），EPUB / MOBI / AZW3 / TXT 取**当前这一节解析出的正文**（0.25.0），两者都进同一个「带材料追问」的入口；空态开场与快捷提问条与文章伴读同款。**快捷提示词按场景分两套**（设置 → 快捷提示词）：文章伴读与电子书伴读各自增删改，电子书的提问以「当前这一页」为单位，扫描页无文字层时禁用。扫描版没有文字层时**明说看不到这一页**，而不是凭书名猜内容

### OPML

导入（含嵌套分组扁平化）、预览去重、按需选择、导出

### 订阅管理

未读 / 收藏筛选、标题过滤、批量已读

## 阅读体验

### 阅读

正文净化后渲染；字号 / 行高 / 版心宽度 / 六种纸色主题 / 自选设备字体。这一整套在工具条的**「T」按钮**里（0.45.0 起）：它原来打开的是文章大纲，现在归阅读设置 —— 「T 是 typography」比「T 是 table of contents」更直白，而大纲本来就该用一棵列表树表示。

- **列表里对着任意一篇右键**（0.45.4）就能「打印 / 存为 PDF · 导出 Markdown · 隐藏这篇文章」，不必先把它打开：打印与导出走**按需取正文**（`getArticle`），因此**不改选中、不把文章标成已读** —— 「导出一篇没读过的文章」不该让它变成已读；版本仍按 `reading.defaultVersion` 取，与打开时看到的那一版一致。
- **第三个菜单项是同一位置的两态**：`entry.hidden` 为真时写「恢复这篇文章」，否则「已隐藏」筛选下列表里会有一条点了没反应的假话。
- **为什么是右键而不是每行一颗「…」**：侧栏只有 256–320px，常驻控件会把标题挤到 130px 以下（0.45.3 刚为封面位量过），而「悬停出现」与右键在发现成本上是一回事、后者还不改版式。
- **坐标做的是夹取不是翻转**：贴着窗口右下角右键时菜单被推回界内，而不是翻到上方 —— 翻转让同一次位置右键两次可能一次朝下一次朝上。
- **关掉它有四条路**：点外面、`Esc`、滚动（菜单是 `fixed`，列表滚走后会浮在别的文章上）、窗口 resize；菜单开着时 `j` / `k` / `L` / `/` 全部让位

### 文章大纲

工具条一颗**列表树图标**的「大纲」按钮（0.45.0 起改的图标语义：那颗 `T` 现在打开的是**阅读设置**，列表树才是大纲 —— 用户的原话是「图标 T 改成点击打开的是阅读设置，然后大纲用这个图标」，而在此之前 `T` 开着大纲、阅读设置藏在「…」里）。它把正文的 `h1–h4` 列成目录，**层级缩进、点击跳转、滚动时高亮当前节**。浮在阅读区右上、**不挤压正文**（挤压会让正文重排、正在读的那行跳走），滚多远都钉在视野里。

- **标题从渲染后的 DOM 里取**，不从 HTML 字符串正则匹配 —— 净化会丢掉不认识的标签，正则数出来的标题可能根本不在页面上；译文 / 改写两条路径的标签结构也不一样。
- **空标题不进目录**（有的源拿 `<h2><a id="x"></a></h2>` 当锚点，收进去就是「点一行、页面纹丝不动」）。
- 没有小标题时按钮禁用并写明原因 —— 点了什么都不发生的按钮就是「看起来像功能」。
- 跳转自己算 `scrollTo` 目标、**不用 `scrollIntoView`**（后者会把外层所有可滚动祖先一起滚，滚完左侧列表也跟着跳）

### 长文阅读

**文章大纲**（浮层里点标题跳转，滚动时高亮当前节）· **朗读**（系统语音，四档语速）· **打开即回顶**（0.84.5 撤掉旧的阅读位置记忆：点开一篇却落在上回读到的末尾，像打开了另一篇）· **隐藏文章**（可撤销；筛选行里的「已隐藏 N」是兜底入口）· **导出 Markdown**（导的是**屏幕上这一版** —— 在读译文就导译文）· **选中文字就浮出操作条**（「摘录到灵感」/「问 AI」两颗，不用再绕「…」菜单）· **摘录进「灵感速记」**（`meta.article` 记文章 key，日记里能反查回原文）· **每个源各自记住**筛选 / 搜索词 / 列表滚动位置

### 划词操作条（0.45.0）

选中正文里的任意一段，选区上方就浮出一条小工具条：**「摘录到灵感」**（直接写进今天的灵感速记）与**「问 AI」**（带这段进右侧伴读）。

- **不再「一选中就自动打开伴读面板」**：面板一开 `.npr-layout` 从两列变单列、正文区整体变宽，刚选中的那段**在屏幕上跳一下**，浮出来的操作条也会锚在旧坐标上；只想记一句话的人还得先关掉一个面板。**但伴读面板本来就开着时仍跟随新选区** —— 那时布局早就是两列了，不存在跳动，而用户的意图明显是「就这段问 AI」。
- **定位抽成纯函数** `selectionBarPlacement`（上方放不下翻到下方 / 左右夹进窗口 / 空选区不浮条），因为这几条边界埋在组件里就只能靠肉眼在真机上碰。
- **点工具条自己不算「点外面」**（`closest('.npr-selection-bar')`）—— 漏掉这一条，按钮会在 `click` 之前就被卸载，症状正是「点了没反应」。
- 按下按钮 `preventDefault`，否则那一下把选区折叠掉、高亮当场消失。
- 收起条件三条：点外面 / 滚动 / `Esc`；只写点外面的话，滚动时它会停在半空，像贴在别的内容上

## 播客、字幕与语音

### 朗读

工具条一颗播放 / 暂停，语速（慢 / 正常 / 快 / 很快）在「更多操作」里；**设置 → 朗读**是这套偏好的固定住处（0.76.1 起；0.76.2 重排成「云端语音 / 朗读偏好 / 念准多音字」三组，长解释收进折叠），与阅读页的 ⋯ 菜单、电子书浮动列读写**同一把键**，改完立刻生效、不会出现两处各存一份。

- **没有中文语音时不退回英语**：那会把中文用英语音素念成噪音，比不念更糟 —— 界面直接说「这台机器没有中文语音」。
- **本机语音优先于在线语音**：在线语音断网时**静默不出声**，用户会以为按钮坏了。
- **按句末标点切块**（600 字/块）：Chromium 对超长 utterance 会**静默截断**，用户听完开头就静音、还以为读完了。
- **切文章 / 切版本时停朗读**，否则上一篇会继续念而屏幕上是另一篇。
- **不做逐句高亮**：高亮要把正文切成一句一个 `span`，而正文是 `dangerouslySetInnerHTML` 塞进去的 —— 切一次整棵子树重建，滚动位置会跳、选中会丢、划线也失效。
- 电子书用的是**同一个引擎**，入口在书本页的「听本节」，见下面那行。
- **带音频的播客单集把朗读灰掉（0.84.1）**：这一集本来就有真人音频，再合成一遍文字稿只会让两条声音抢同一个场景 —— 按钮 `disabled`、透明度降到 .38、鼠标不是手型、悬停不高亮，标题与 `aria-label` 写明「这一集自带音频，用播放条收听」

### 单集音频与字幕（0.81.0）

订阅源里的**播客单集**能开听，而且能跟着字幕读。

- **文章 / 字幕 / 导读 三选一（0.84.1）**：三态互斥 —— 文章态只显示正文，字幕态与导读态各显示一块面板，导读不再压在 120 段字幕上堆成一长页；**播放条在上、选项卡在下（0.84.2）**，tab 是一排无底座的文字、选中项只有一条 2px 下划线（照用户给的参考图重做，旧的灰胶囊 + 白滑块夹在标题和播放条中间，看着像第二组播放控件）；播放条右端那颗冗余的「字幕」按钮已撤掉，入口只有 tab 一处。**标题在三态下同一套字号/行高/字重（0.84.3）**：文章态与收听态是两个 `<h1>`，以前各写各的（21px vs 24px），切一下标题就变小，现在共用一条规则，只留各自不同的 margin。`data-listen` 与 `data-read-tab` 从**同一个** `readTab` 派生，两块面板都常驻 DOM 靠 CSS 白名单显隐（条件渲染会卸掉字幕面板、把刚接上的 `audioController` 弄丢）。
- **播放器常驻**：播放条的渲染条件只有 `audioUrl`，三个 tab 下都是同一个节点，`<audio>` 从头到尾不卸载（卸载就等于换了播放器、位置归零）；选项卡条带 `data-listen-keep`，切到收听态后仍切得回来。
- 正文整块让位；用 tab 里的「文章」返回（0.84.5 去掉标题上方那颗重复的「回到文章」按钮），音频不断。
- **音频走宿主中转**（`/library/audio`）而不是外链：播客托管普遍「短链 302 到 CDN」，而 302 那一跳不带 `accept-ranges`，浏览器就退化成全量顺序下载 —— 一集 106 MB 要缓冲很久，界面停在 `00:00 / 00:00`；中转层主动带 `Range` 发出、把 `206` 与 `content-range` 透传回来、上游没给 `accept-ranges` 时**自己补一句**，且每一跳重定向都过 SSRF 校验。
- **点一段就跳到那一段**；从导读点时间戳时**先切到字幕页再 seek + 滚动高亮（0.84.4）** —— 三选一之后字幕面板是隐藏的，不切页就没法「跳回原话」。当前段用 `inset` 细线 + 底色高亮，**不自动滚动**（往回看两句是常事，手动出口是「回到正在播的一段」）。
- **语言三态一个按钮**：原文 → 双语 → 中文，译完第一批自动进「双语」但**只推一次**。
- 字幕只读订阅源自带的（Podcasting 2.0 `<podcast:transcript>`；WebVTT / SRT / 官方 JSON 三种都认，**内容嗅探优先于 feed 声明的类型**）；源里没有就明说「这一集没有字幕」，并在空态给出「本机识别」（0.82.0，见下一行）。
- 断点与倍速按集记在本机（`localStorage`，5 秒落一次 + 卸载补写）。
- 切段规则：间隔 ≤1.2 秒并段 / 单段 ≤220 字 / 句末且 ≥60 字才断，字幕缓存在 `transcripts/`

### 没字幕时的本机识别（0.82.0）

订阅源没给字幕**不等于这期读不了** —— 中文播客（硅谷101、忽左忽右、半拿铁、知行小酒馆）实测**一个都没有** `<podcast:transcript>`，英文源里也有一大批给的是 `text/html`（解析不了）。「这期没有字幕」那个空态现在给出路：点**「本机识别」**，在你自己这台机器上把音频转成字幕。

- **音频不出本机、不需要任何 key**：不选云端 ASR，就是为了这两条（一集播客的收听记录不值得先上传，想读懂一期也不该先办张卡）。引擎是 CrispASR（whisper.cpp 兼容实现，17.8 MB 单体包），**按需下载到插件数据目录 `asr/`**、不塞进安装包 —— 删掉这个目录就等于卸载干净；也**不要求 `brew install`**（那会连带升级 llama.cpp / libomp / openssl 一串系统包）。
- **首次要点一次下载**：引擎 17.8 MB + 模型 181 MB（默认 `small`；`base` 对中文明显不够，把「孵化器」听成「复化器」），**带断点续传**（实测同一条镜像链路时快时慢，不续传的话一次抖动就从零再来），进度条按体积分账（引擎 8% / 模型 92%）。
- **解码只做一次**：整段转 16 kHz 单声道 WAV（54 分钟音频实测 28.4 秒），再按 **5 分钟一片**用 `-ot` 毫秒偏移读同一文件的不同区段 —— 每片单独从网络取的话，5 分钟片光 302 握手与 MP3 粗粒度 seek 就要好几秒。
- **时间轴是真的**：`-sp` 按句末标点切行（不加时引擎把整片吐成一条 cue，高亮与点句跳转全失效），第二片的时间戳从 `300.0s` 起而不是归零。
- **简体 + 专名**：whisper 中文默认输出繁体，提示词里一句「用简体中文转写」直接变简体；标题与节目名进提示词能纠回专名（实测 `HFZERO` → `HF0`）。
- **幻觉过滤**：静音处模型会编出「谢谢观看」「请不吝点赞」，只在**短且无上下文**时删（说了 40 字还提到「订阅」的是真话），相邻重复与跨片重复也删。
- **进度是逐片的**（第 2/11 片 · 已出 35 段 + 最近 3 句原文），随时能停，**停止不落盘半份字幕**；识别状态放在阅读页而不是面板里，切走再回来进度不归零。
- 缺 `ffmpeg` 时**不给按钮**、直接写 `brew install ffmpeg`（点了只会吃 409，还得先下 181 MB）。
- 临时 WAV 用完即删（两小时音频 230 MB）

### 没字幕时的识别：三档引擎（0.84.0）

0.82.0 只有本机 CrispASR 一条路，0.84.0 变成三档，默认 **Qwen3-ASR 0.6B**：**① Qwen3-ASR（默认，走本机 Ollama，约 1.0 GB）** · **② 云端 ASR**（Groq / 硅基流动 / OpenAI / 豆包 / 自定义 OpenAI 兼容端点）· **③ 本机 CrispASR**（0.82.0 那条，保留兜底）。

- **Qwen 走 Ollama，不自带第二个推理二进制**：Qwen3-ASR 的 GGUF 要 `transcribe.cpp`（不是 whisper.cpp / llama.cpp），为一个模型多背 20 MB 不划算，而本机多半已经有 Ollama。
- 官方 registry 名 `qwen3-asr:0.6b` **不存在**（`Error: pull model manifest: file does not exist`），能拉的是 `frozenlab/qwen3-asr:0.6b`（1.0 GB）⇒ 拉取时先试短名、失败自动退社区包（`OLLAMA_ASR_PULL_NAMES`），不把「哪个名字能拉」写死在界面文案里。
- **输出带前缀**：`language Chinese<asr_text>今天…`，语言标记与正文之间是**字面量 `<asr_text>`** 而不是换行 —— 不削掉，第一句字幕就是「language Chinese」。
- **它不返回时间戳** ⇒ 按 **30 秒**切片（准确率在 60 s 窗口内才平稳），片内按字数比例分配（`splitSliceText`）。实测 87 分钟真实音频：解码 11.6 s、之后 263 ms / 30 秒片、断句与专名（刘裕北伐 / 程彦良 / 张诗平）都对。
- **云端**：OpenAI 兼容用 `verbose_json` 取 `segments`（拿不到就整片一段并标 `degraded`，不假装有时间轴）；豆包是 submit + 轮询（`x-api-status-code` 20000001/2 = 处理中）；音频按 10 分钟切片、48 kbps 单声道上传。
- **会上传就明说**：空态与设置页各一句「云端识别会上传音频」，不藏在 tooltip 里。
- **点名的引擎不会被偷偷换掉**：选了云端就不在本机跑、选了 Qwen 就不退 whisper；用不了就把原因写出来（缺 Ollama / 缺模型 / 缺 Key），而不是「帮」用户换一条路 —— 那会让他以为选的那条已经生效。
- **Key 只写不读**（`publicSettings` 里显式 `delete`），并登记进 `settings-patch.js` 的 `LIVE_WRITTEN_SETTINGS` —— 否则每点一次「保存」就把 Key 清空一次

### 字幕翻译：Google 优先（0.84.0）

设置页 → **字幕与识别** → 翻译引擎三档：`auto`（默认：先 Google，剩下的再交给模型补齐）/ `google`（只用 Google，翻不全就**明确报错**并指路设置项）/ `model`（只用模型）。

- **为什么 Google 优先**：字幕翻译量大、重复、对智力要求低 —— 一集 120 段要 6 批模型调用、一两分钟、每翻一集都花钱；免费端点几百毫秒给完，重翻一集也不心疼。模型这条腿**保留**（术语多、口播绕的集子明显更好），不是被替代。
- 端点是 `translate_a/single`，两个域名都试（不同 CDN，一个被封时另一个偶尔还通），**顺序固定不随机** —— 随机化会让「同一台机器时而能值时而不能」无法复现。
- **POST 表单体而不是 GET**：一集字幕串进 query 会顶到 2 KB 以上，某些中转在那层截断，症状是「最后几段永远是空的」。
- **必须带 UA**：不带 UA 时 Google 回一个**空数组**（状态码 200），从状态码什么都看不出来。
- **行数对不上不硬塞**：Google 偶尔把两行合成一行，按行号分配会把译文整段错位（界面上全是中文、看不出错）⇒ 改成逐段重发，宁可多几次请求。
- **「答了但没有一个中文字」也算不可用**：否则界面会说「Google 漏了 N 段，已用模型补齐」，而真相是它根本没在工作。
- 译文记 `via`（`google` / `model:<名>` / `google+model:<名>`），界面上那行小字写的是**这一次实际用了哪个**

### AI 导读 + 点时间戳跳回原话（0.84.0）

收听视图顶部一张导读卡：**4–8 段章节**，每段一句「这一段在讲什么」+ 一条**逐字引用**的原话 + 这一段出现的人物。每段左边一个 `[mm:ss]`，点一下**先切到字幕页**，再把音频 seek 到那一段开始播、字幕滚到那一段高亮（0.84.4）—— 「跳回原话」要连声音一起回；三选一布局下字幕页是隐藏的，不切页连滚都滚不到。

- **时间戳可信靠两道保证**：提示词要求照抄输入里的 `[mm:ss]`；解析时再 `snapToParagraph` 把每个时间**吸附到真实存在的段落起点**上 —— 模型把 12:30 写成 12:28 是常态，照它跳会落在两句之间，而看起来像「跳错了」。
- **分两次调用**：进面板只读缓存（`episodeDigest(key,false,false)`），点了「生成导读」才花钱（`generate:true`）—— 打开一集就自动跑模型，等于每次点开都在扣钱。
- **长片等距抽样**：字幕超 **1.2 万字**（0.84.1 从 3 万字收紧，避开小模型的输入上限、也省额度）按等距抽样并插 `…`，卡片上标「长片抽样」—— 直接掐尾巴会让导读只覆盖前半集，而界面上看不出这件事。
- **没字幕时给的是出路不是空白**：写「先识别这一集」，不给「生成」按钮。
- 章节行**不是带边框的卡片**：`<div>` + 网格 `58px 1fr`，只有时间戳是可点的 —— 整块看着像按钮，用户会去点正文。
- **报错说人话（0.84.1）**：宿主只给 `INVALID_REQUEST`、原文提到 `max_tokens` 时，改说「模型不接受这次请求的输出长度，不是文章太长」；宿主**压根不给码**（OpenCode 免费额度那种一整段英文）则按原文关键词归成「这个通道的免费额度用完了，等窗口重置或换通道，换模型没用」。
- **结构化码优先、只在有证据时细化**，认不出就原样透出原文；文案带实际用的 provider/model，并留一行 `~/.dsh/npie-reader-diag.log` 现场。
- **前端按钮跟着分流（0.84.4）**：额度耗尽显示「换好通道后再试」并点破换模型没用，输出上限显示「换模型后再试」并点破不是文章太长；认不出才落回「再试一次」

### 书架（电子书）

顶部「订阅 / 书架」切换。列出**你勾选载入的那几份书单合并成的**全部书（**只读**），合并时按书 id 去重。书单由设置页的「电子书书架」三步产出（见下一行），**默认一份都没有** —— 走完那三步才会有书。你已有的那份整理好的书单也能用：在第三步的「外部书单」里填路径（**留空 = 不用**）。点开即在阅读区按**原版式**渲染 PDF —— 内置 pdf.js，不重排、不转文本。界面把**书单的解析后绝对路径**显示出来，所以「以为在读书单、其实在读空气」不会悄悄发生。

- **EPUB / MOBI / AZW3 / AZW / TXT 点开就是重排阅读**（0.25.0）：宿主侧解包 / 解压出文字与章节，界面按**块模型**重建段落、标题、引文、列表 —— 还原文字与章节层级，**不还原图片与原版式**（要原版式请先转 PDF）。
- **「一节 = 一页」**：节号、页码、目录跳转目标、阅读进度、伴读的「当前页」全是**同一个数**，所以电子书直接复用 PDF 那条 `pages.jsonl` → 分段 → 逐章解读的链，不另起一套进度体系。
- **一页 = 一个正文标题块**（0.25.1）：切页看的是正文里的 `h1–h6`，**不是 EPUB 的 XHTML 文件** —— 《九三年》21 个文件装 23.9 万字，一个文件就是一整卷，翻一页等于读 1.5 万字，目录点小节也回不到那一小节；按标题切之后是 **103 页、页均 2041 字**。目录因此按**章 / 节两级缩进、页码顶右**（纸质书目录的样子），页眉（书眉）只写**所属的部 / 卷**（不写当页标题 —— 那就在正文第一行，写两遍是重复）。
- **顶部胶囊与 PDF 阅读器是同一套**（0.25.3）：`.npr-book-chrome` + `.npr-book-pill` 原样复用，连类名都不另起，所以外观不是「做成一样」而是**本来就是同一个**。它必须待在 `.npr-book-main` **外面**：0.25.1 曾把胶囊并进书页那个 sticky 页眉，结果一开目录 / 划线 / 伴读，阅读列变窄、胶囊跟着挤，最后那颗「沉浸」被裁到纸面外面（用户截图里的「出框」）—— 胶囊属于**窗口**，宽度只跟窗口变。窄窗口下先把按钮文字砍掉只留图标（**760px**，胶囊 467 → 264），再窄一点连书名也收掉（**560px**）—— 两个阈值是**量出来的**：胶囊在真 Chrome 里的实宽分别是 467 / 264 / 204，减去书架列 236 与 chrome 内边距反推出 727 / 524 / 464，各留约 30px 余量；0.25.1 那版按 920 / 640 砍，920 比实际需要多砍了将近 200px，900 宽的窗口明明放得下却只剩一排图标；**不用 `overflow: hidden` 硬裁**：被裁掉的按钮仍然能 Tab 到、却点不到。
- **书眉一律占位**：顶层页（部 / 卷扉页）不写所属章节，但那一行 34px 照样留着 —— 整行不渲染会让纸面上边沿在两种页之间跳 34px，翻页时纸会抖一下；这条横带本身就是纸色，空着看不出来。
- 外观与 PDF 同源（字号 / 行距 / 版心 / 纸色 / 亮度）：`←` `→` 翻节、`I` 沉浸、`N` 换配色、`Esc` 逐层退，右下角浮动按钮装「当前这一节」的调档动作（节号 / 上一节 / 下一节 / 字小 / 字大）；顶部胶囊是「这一本」的开关类动作 —— 标记读完 / 伴读 / 划线 / 目录 / 配色 / 沉浸。
- **解读不占按钮**（0.25.2，用户原话「菜单条为什么会有解读这个按钮，打开又和目录差不多，建议去掉，解读还走目录」）：它打开的是一张章节列表，而那正是目录已经有的东西 —— 两个入口通向同一屏，第一眼分不清差别。现在**唯一入口是目录面板底部的「逐章解读」**（有解读时显示「解读 N 章」）：先看目录（免费、书自带），想花钱要解读时再往下走一步。
- **正文直接建成 React 元素**（`h1` `h2` `h3` `p` `li` `blockquote` `pre`），**不用** `dangerouslySetInnerHTML` —— 电子书是外来文件，走 HTML 注入等于把 XSS 面开到最大。DOCX 仍标「暂不支持」并给出路径（网盘路径或本地路径），让你能直接去访达里打开。阅读器带**适应宽度 / 适应窗口**两态（一键切换，另有手动倍数），窗口尺寸一变就重算；**方向键与滚轮都能翻页**（滚轮按滚动位置分流，见下方「阅读器的缩放与翻页契约」）。
- **操作分两层**（0.23.0）：**顶部一颗胶囊**装「这本书」的**开关类**动作 —— 标记读完 / 伴读 / 划线 / 目录 / 配色 / 沉浸，共 6 项（读的时候不常点，也不该占着右下角那块「鼠标常去」的地方）；**右下角一颗圆按钮**装「当前这一页」的**调档类**动作 —— 页码 / 放大 / 缩小 / 适应窗口 / 适应宽度 / 下一页 / 上一页，共 7 格。
- **鼠标移上去就展开，点一下也展开**（0.24.3 从「只认点击」改回来）：展开后是**竖直一列**，每格是**圆形图标 + 左侧文字标签**（`--npr-fab-x/y` 定位、`--npr-fab-size` 定尺寸、`--npr-fab-i` 逐格延迟）；整列从按钮往上排，最上面那格再向左让出一点弧度（`fabStack` 的 `bend`）。为什么这次敢用悬停：按钮与第一格之间必定有一段空隙，鼠标经过空隙时指针既不在按钮上、也不在格子上 —— 0.23.0 据此把悬停整个删掉，但那是**观察对、结论错**：缺的是**宽限期**，不是悬停不成立。现在离开整棵子树后等 `FAB_HOVER_GRACE`（220ms）再收，横穿 8px 只要 30–80ms，慢手也不到 100ms。开合仍然只认 `.is-open` 这一个类，**一行 `:hover` 规则都没写** —— CSS `:hover` 管不了「跨空隙不断」，而挂在祖先上的 `pointerenter` / `pointerleave` 只在「进入 / 离开整棵子树」时触发，按钮→格子、格子→格子都不会误收。**点击保留**（不是回退）：触屏没有 hover、键盘要能 Tab 到按钮再回车，它们是「钉住 / 收起」的显式开关。为什么是**竖列**而不是绕按钮扇开：扇开的那 7 颗圆片彼此挤在一起、又没有文字，既认不出是什么、也点不准（「这个效果简直丑爆了」）。为什么不再是顶部横条：横排工具栏功能一多就**必然**在某个宽度上把右边裁掉，而溢出部分不接收点击 —— 用户报的原话就是「不是全屏就会被截断，好几个功能按钮显示不出来」。
- **按钮钉在「阅读区」而不是整个面板**（0.24.3）：舞台与按钮都放进一层 `.npr-book-view`（`flex: 1`、不滚、不画东西），按钮的 `position: absolute` 以它为基准 —— 一开伴读右侧多一栏时，按钮仍贴书页区右下角 14px，不会跑到伴读的角上。**不能直接放进舞台**：那是 `overflow: auto` 的滚动容器，绝对定位子节点会跟着内容滚走。为什么是**竖列**而不是绕按钮扇开：扇开的那 7 颗圆片彼此挤在一起、又没有文字，既认不出是什么、也点不准（「这个效果简直丑爆了」）。为什么不再是顶部横条：横排工具栏功能一多就**必然**在某个宽度上把右边裁掉，而溢出部分不接收点击 —— 用户报的原话就是「不是全屏就会被截断，好几个功能按钮显示不出来」。
- **沉浸式阅读**（`I`，`Esc` 退出）：**只收占位与干扰，不收控件**（0.24.6 改回来）—— 元信息行藏掉、**左侧两列一起 `display: none`**（书架列与它右边那条拖动分隔条），正文从面板顶端铺到底端；**窗口大小不变**（0.24.2 起不自动全屏）。
- **顶部胶囊不消失，改成「鼠标移到顶边滑出、离开收起」**：`absolute` + `translateY(-100%)` + `opacity: 0` 收起（脱离文档流，那几十像素真的还给书页），收起时 `pointer-events: none`，否则挡住书页顶部的划选。
- **滑出的判据是「指针离面板顶边多近」，不是 `:hover`**（0.25.4 的真机故障）：一开始拿顶部那条 `data-window-drag` 的 10px 拖动条当热区、靠 `:hover ~` 兄弟选择器滑出 —— 可那条在宿主里带 `-webkit-app-region: drag`，Chromium 把它当窗口标题栏命中（`HTCAPTION`），**页面收不到任何鼠标事件**，`:hover` 永远不成立，于是胶囊滑出去就再也滑不回来（用户原话：「顶部的菜单条一旦隐藏就出不来了」）。现在按 `pointermove` 算「`clientY − 面板顶边`」：**≤56px 滑出、>72px 才收**（滞回写在纯函数 `book-peek.js`，两个阅读器共用、有 9 条单测）；指针从**顶部**离开面板时**不收** —— 那正是用户伸手去点它的那一刻。
- 顺带记一笔**假绿**：`check-book-reading-chrome.mjs` 里「真指针悬停能滑出」那条一直是绿的，因为它自己搭的探针页**没有** app-region 声明，而这条 CSS 又只在该声明的缺席下才成立。
- **0.25.7 补两个约束**：① **指针落在面板上时一律不滑出**（`insidePanel`，沿父链认 `.npr-book-digest` / `.npr-marks` / `.npr-companion`）—— 关面板要点的「收起」就在面板顶部那一行，判据只看 y 的话鼠标一往上移胶囊就滑出来盖住它；已经滑出的要**立刻收**，只 `return` 不够。② 沉浸 + 左侧面板打开时胶囊**让位**到面板右侧（`has-side` + `--npr-book-side-w`，只在 `@container (min-width: 821px)` 里生效）—— 胶囊原本 `left:0; right:0` 满窗口铺开再居中，窗口一窄左端就压进面板右缘。窄容器（≤820）下面板改成上下排、铺满整宽，那时胶囊无处可让，只能靠 ①：退出沉浸走 `Esc` / `I`。
- **右下角那颗按钮常驻可见**（0.24.6 删掉了「沉浸态设成透明」那条规则）：0.24.2 把控件藏光是错的，用户原话「原来的浮动工具按钮为什么没有了，应该存在啊」。
- **全屏是用户对窗口的决定**，不由「我想安静读一页」代劳（macOS 全屏会换一个 Space、有动画、退出还要再按一次），所以两件事**解耦**：沉浸只改布局，全屏由 `⌃⌘F` / `F11` 触发 —— 0.24.6 之前那句提示是**假话**（`readerCommand` 遇修饰键直接 `NO_COMMAND`，既没人处理也没人 `preventDefault`，按下去完全没反应）。
- 代价要说清：宿主自己那一列（新会话 / 技能 / 插件…）在插件**挂载点之外**，插件改不到它的 CSS ⇒ **不进全屏就收不掉它**；沉浸态收的是插件自己的两列。
- **书页配色面板**：点「配色」展开一块调色板 —— 一条**亮度滑杆**（70%–130%，设置项 `bookBrightness`，松手才写盘）加四个**色块**（原色 / 护眼 / 薄荷 / 夜间，设置项 `bookTint`）。配色是「我要哪一个」的选择题，所以给色块而不是只给 `N` 轮转（四档之后轮转要点 1–3 次才到位，`N` 仍然保留）。PDF 是位图，改 CSS 纸色对它毫无作用，所以是**两层**：① 整层 `filter` 管像素颜色 —— 护眼是 `sepia` 系 + 米黄舞台底，薄荷是白天用的护眼档（只偏色相、不反相，彩色插图不会被翻成负片），夜间是 `invert + hue-rotate(180deg)`（只反相会让彩色插图变底片）；滤镜只加在**画布**上，不加在画布与透明文字层的共同父级，否则 `::selection` 的高亮也会被反色。② **纸色覆盖层**（0.24.3）管「白纸本身」—— 滤镜是按像素算的，白纸乘出来仍是白，所以另压一层 `mix-blend-mode: multiply` 的 `.npr-book-tint`：白纸 × 米黄 = 米黄，黑字 × 米黄 ≈ 黑字。**必须是 multiply 而不是普通半透明**（后者会把黑字一起提亮，文字发灰比白纸更难受），且它插在**画布之上、文字层与划线层之下**（靠 DOM 顺序，不用 z-index）—— 那两层要保持原色，否则选中高亮与划线色块也被染成纸色。原色与夜间两档**不叠**：原色本来就是对色，夜间是反相出来的黑纸、再乘一层深色会压成死黑。亮度则加在**舞台**上（书页与四周那条空隙一起变暗，不然调暗后是「一张灰纸镶一圈白边」），且**不碰浮动按钮与面板** —— 它们是控件，不是书页。
- **持久划线 / 笔记**（0.21.0）：拖选一段字，气泡里多出「划线 / 笔记」；线落在 `annotations/<bookId>.json`，锚是**页内字符偏移 + 摘录原文**（不存坐标 —— 坐标随缩放/适宽变化，存下来一刷新就错位），所以换缩放、翻页、重启都在。左边面板两个页签（全部划线 / 有笔记），卡片是「摘录 + 页码 + 我写的笔记」，点摘录跳到那一页，四种颜色与删除都在这儿。
- **头部一颗「导出」**（0.27.0）把整本划线复制成 Markdown：**导出全部、不按当前页签筛**（在「笔记」页签上点它，期待的也是整本）；与 `book_annotations` 工具**共用同一份格式化**（`src/annotation-format.js`），所以模型读到的和你复制走的是同一段文字；结果写在按钮上（「导出」→「已复制」/「复制失败」），不额外占一行 —— 306px 栏里每多一行就把下面那叠卡片往下推。高亮层 `pointer-events: none` 是硬要求：它一旦能接点击，划过线的文字就再也拖选不了，而拖选正是划下一条的入口。
- **电子书同样能划线 / 笔记**（0.25.2）：同一个面板、同一份 `annotations/<bookId>.json`，但锚点换成**「第几块 + 块内第几个字」**（`src/client/ebook-marks.js`）—— PDF 那套「数文字层文本节点」在重排正文里数不准（块与块之间隔着元素边界），而每页的块区间是把所有非空块用 `\n` 串起来算的，与伴读读到的正文**同一个基准**。高亮**直接写进文字里**（`<mark>`）：PDF 是在位图上另铺一层绝对定位的矩形，而重排文本的坐标随字号 / 版心 / 窗口宽度一直在变，量矩形等于每次改字号都要重算一遍

### 听本节（0.76.0）

电子书页右下角浮动按钮里的「听本节」：把**当前这一节的纯文本**交给文章那边已经跑了一年多的朗读链路（本机语音 / 硅基流动，音色、语速、计费估算、sha1 内容寻址缓存全部复用），**合成、缓存、音色、计费一行没重写** —— 唯一的区别是正文从哪来（文章读 `innerText`，电子书读块模型里的纯文本行）。

- **读位与听位分开**：听位单独存 `npr.ebookListen.<书 id>`，听着第 3 节、眼睛翻到第 9 节时读位仍归翻页管；两者写成同一个值是最容易犯的错（注释写着互不干扰、代码里两组字段同时赋同一个值）。
- **三道停播门**：换节换书 / 切到别的标签页 / 组件卸载 —— 只做卸载时，桌面端切 tab 不会卸载组件，声音会一直念上一节。
- **定时关闭**：15 / 30 / 60 分钟，到点**真停引擎**（两条引擎都停，只停当前那条会留下双声）；没在播时到点**静默**清掉（半夜弹一句「已停止朗读」只会把人吵醒），重新点播放**不重置计时**（否则每翻一页就续命）；不落盘 —— 定时是「这一次」的意图。
- **念准多音字**：19 条高把握词（行李 / 重庆 / 会计…）只在**送合成之前**换文本，屏幕上看到的正文一个字不改；设置页可关。变换放在切块之前，所以跨块的词（「甲乙行李丙丁」按 4 字切）也不会漏。
- **按节导出 MP3**：两段式，第一次只报价、一个请求都不发，第二次才合成；无损拼接不依赖 ffmpeg，取消 / 失败都不留半个文件；上限 36 KB ≈ 12000 字，整本 19 万字会被直接拒绝并说明（按字节计费，整本约 ¥28）。
- 这是**电子书页**自己的浮动列（9 格，`BookEbook.jsx`；0.76.1 加了第 7 槽「语速」，点一下换档 慢 / 正常 / 快 / 很快 —— 正在播时改语速会**先停**，且**不自动续播**：云端缓存键含语速，换档要重新合成、重新计费，自动重播等于替用户花钱），与 PDF 阅读器那套 7 格（`BookReader.jsx`，以及 `scripts/check-book-reading-chrome.mjs` 逐条核的那 7 格）**不是同一个组件** —— 后者一个字节没动

### 书源（电子书从哪来）

设置页 → 电子书书架，**按操作顺序三步**：① **电子书源渠道配置**（本地电子书目录 + 百度网盘目录，网盘走内置授权向导 + 目录选择器）② **生成书单**（**每个目录各生成一份**，可单独重扫；书单名自动取目录名、生成前可改）③ **载入到书架**（一次勾选**多份**）。书单写进**插件数据目录**的 `lists/` —— **一条源 = 一份书单**，所以「只想先看一个目录」不需要把别的也扫一遍。

- 扫描只产出它拿得到的东西：`series`（丛书名）/ `year` **刻意留空** —— 文件名里的 `[古罗马]` 是**国别**不是丛书，猜出来的值会让「按丛书分组」把书归错类。
- **id 跨次扫描稳定**：阅读进度按 id 记，重新生成书单一换 id 就等于**把全部进度清零**，所以重扫时优先复用「同源同文件」的老 id。
- **外置盘没挂上时点「生成」不会清空已有书单**：只跳过「一本都没扫到 + 根目录有错」这一种

### 不像书的 .txt（0.76.0）

本地扫描时**抽样前 64 KB** 判一下「这到底是不是一本书」（设备配置、日志、`requirements.txt`、纯英文清单…），命中就在书单那一行标一句「可能不是书」。

- **只标不排**：照样列出来、照样能打开 —— 判错一次就把用户的书藏起来，代价远大于多看一眼。
- **只搬过滤、不搬解码**：仍走原有那条严格 `TextDecoder(fatal)` 解码（宽松解码反而会把「压根不是文本」的东西读成一堆替换字符）。
- 网盘书不标：要判就得先把整本正文下下来，不值。
- 判据刻意避开两种真实误伤：40 行 `ip address 10.0.0.x`（小数点不是句号）、以及行数不够的短清单（样本不足就不下结论）

### 本地书的读取边界

本地书走一条**本机文件通道**（loopback HTTP + `Range`），而宿主派发插件路由**不经过**它自己的鉴权拦截器 ⇒ 这条通道上的三道闸就是全部防线：① 必须落在**你配置的目录**之内（没配任何目录时一本都读不了，不是全放开）；② 先 `realpath` 再比对（挡 `../` 与指向外面的符号链接）；③ 比对时补分隔符（`/books` 不得匹配 `/books-old`）。扫描侧另有一条：**不跟符号链接**

### 电子书目录

阅读区工具条上的「**目录**」：把整本书的正文抽出来、切成章、在**书页左边**列出来（0.19.0 起；此前在右边），**点一下就跳到那一页**。

- **目录在左、伴读在右**：目录是导航类，视线从左上往下扫、再落到右边的正文；伴读是对话类，与订阅那半边的伴读同侧。位置靠 **DOM 顺序**（目录写在书页之前、伴读写在之后），不用 CSS `order` —— 读屏与 Tab 顺序跟着 DOM 走，用 `order` 挪视觉会让键盘用户先跳进正文、再 Tab 回目录；`order` 只在**窄窗口竖排**时把书页提到第一位（否则目录会顶到最上面，把正文挤到屏幕下半截），那时两块面板都撑满宽度、分隔线改到上边。
- **抽取在渲染进程做，宿主只负责存** —— 宿主有取字节的能力但**没有 PDF 文本解析器**，而 pdf.js 本来就在渲染进程里跑，且本地书与网盘书是同一条路。每 20 页 POST 一批落盘 ⇒ 面板关掉再打开能**从断点续抽**，不用从第 1 页重来。
- **四档降级**（`src/host/segment.js`，纯函数、可单测）：`outline`（PDF 书签）→ `toc`（书前目录页，反查正文定位）→ `heading`（正文里的「第 N 章 / Chapter N」）→ `window`（按页窗切，标题写成「第 12–28 页」）。
- **真机数据推翻了原方案的主力档**：抽 22 本本机 PDF，**只有 1 本带书签（5%）**，所以 `outline` 指望不上；真正能用的是 `toc` —— 目录页条目标题与正文章节首页**逐字相同**，用有书签的书当标准答案交叉验证，11 条可比条目里 **10 条精确、0 个差一页**（唯一错误是「版权信息」这种在多卷里重复出现的标题）。
- **扫描版早退**：32 本抽样里 9 本（28%）整本没有文字层 —— 这不是边缘情况，所以判定放在**最前面**，界面直接说「读不了，要先做 OCR」，而不是先算出一堆章节、再在生成时一页页失败（0.28.0 起这一步改成「识别过的页先顶上」：见下面「扫描书也能有目录了」）。
- **目录页靠「行尾标点」认，不靠字符数**：实测目录页的「行尾无句读比例」恒为 **1.00**，正文页在 **0.54–0.96** 之间波动；最初用「字符数 < 900」当主判据时，把目录页（572/628 字符）全排除了、又把正文页放了进来，切出 43 个叫「2025年11月」的假章节。
- **卷标题页标成「分卷」**（正文不足 50 字且只占一页，如「上册」这类卷名页），不冒充章节。抽取本身**不调用模型、不花钱**。
- **电子书完全不猜章节**（0.25.0）：EPUB 的 `nav.xhtml` / `toc.ncx`、MOBI / AZW3 的 NCX 就是**书自己的目录**，标题原样取出、**一级都不做启发式**（不跑 `toc` / `heading` 那两档 —— 它们是为「没有书签的扫描 PDF」准备的，对结构良好的电子书只会把标题弄错）。所以电子书的分段方式记成 `mode: 'ebook'`，并在 `segmentBook` 里带一个 `assumeText`：它表示「文字是解析出来的、不是从位图里抽的」，**短书不会被「文字太少 ⇒ 当扫描版」误判**（`textRatio < 0.2` 早退这条闸原本是给 PDF 用的）。目录面板里**书自带目录优先**（含层级与字数），层级用于**两级缩进**（0.25.1：部 / 卷顶格加粗、小节缩进一级，页码顶右），没目录的 TXT 才按节平铺

### 书内搜索

打开一本书之后按 `⌘F`（或点胶囊里的「搜索」）在**整本正文**里找词：命中逐处列出来（页号 / 章节 + 片段），回车 / `↓` 下一处、`⇧回车` / `↑` 上一处、**首尾相接**；跳过去时那一处在正文上标出来 —— PDF 是**文字层上重算的命中矩形**（索引文本与 DOM 的 span 序列在「游程之间补不补空格」上可能差一两个字符，能画出来的才叫高亮），电子书是**块内 `<mark>`**。

- **判据与 agent 工具 `book_search` 是同一套**（trim + 小写 + `indexOf` 子串，**不分词**）：两处各写一套的后果是「AI 说第 7 章有，你自己搜不到」，而用户无法判断谁错了 —— 因为这两句话本该是同一个人说的。中文没有词边界，一分词「磨坊主妇」和「磨坊」就变成两种结果，而它们本该是包含关系。
- **不完整的数字必须解释**：`另有 N 页没有文字层（扫描页）` / `命中到 300 处就停下了` —— 不说出来，「共 N 处」会被读成「全书只有 N 处」，那是一句确定的假话。
- **空输入 ≠ 零命中**：前者提示「输入一个词」并写明判据与 `book_search` 同一套，后者说「没有找到『xx』」；合成一句，用户会以为「还没打字就搜过了」。
- 搜完**不自动跳**（`findActive = -1`）：边打字边翻页是最难受的一种交互；此时这一页的命中**仍然全部可见**，只是没有「当前」那一个。
- 搜索是**临时状态**、划线是**存下来的东西**，所以画在**两层**、颜色也不共用 —— 共用一个色系时，用户会以为搜索顺手帮他划了一条线；命中层必须压在划线**之上**（`z-index: 3`），否则「划过线的段落里搜到一处」时当前命中被划线色盖住，按回车看起来像没跳。
- 电子书那边两层的边界**并成同一次切割**（`splitByOverlays`）：命中可能横跨两片划线（先划半句、再划后半句，然后搜一个跨过中间那个点的词），先按划线切再在碎片里找，跨界的命中只剩半截 —— 症状是「搜到了但标错位置」，且不报任何错。
- **扫描页有补救出口**（0.27.0）：搜完发现没有文字层的页时，面板底部出现「**识别这 N 页再搜一次**」，写明「本机识别，不联网、不花钱，约 N 秒 / N 分钟」（按实测 0.8 秒/页估）。**必须是用户主动点** —— 400 页要 3–5 分钟，自动跑等于「搜一个词，风扇转五分钟」，而用户可能只是想确认一个词在不在这本书里。识别结果同时写进**本次索引**（立即生效）与宿主 `ocr.json`（下次打开这本书、伴读那一侧也直接可用）；**识别来的命中标「识别」**，因为摘录里那几个字**不是书上写的**；并明说「跳到那一页标不出具体位置」—— 扫描页没有文字层，矩形无处可算，不说的话「跳过去没高亮」会被读成跳转失效。取消只说「已停止识别」，不说「认出 N 页」（后者会被读成这一批已经跑完了）；但**已认出的页照样保存、照样触发重搜**，提示写成「已停止识别，剩下的页没有试（已认出的 N 页已保存）」—— 停下来不等于白认。单页认不出**不中断整批**，结果里如实报「认出 9 页 · 3 页没认出字」。
- **扫描书不再等用户踩空**（0.27.1，起因：「扫描版 PDF 全文搜索搜不出任何东西」）：打开面板先抽 6 页（首尾 + 中间均分）看有没有文字层，全都空就**在输入之前**把整本索引跑一遍；确认「整本 N 页没有文字层」后，面板直接说这件事（「整本 111 页都是图片，一个字也搜不到 —— 要先认字」），并把按钮升成**实心主按钮「识别整本 111 页，之后就能搜」**。0 命中的那句话同时分成两句：普通书建议换词，扫描书则明说「不是这个词的问题」（换词没用）——在全是图的书里建议换词，等于把人往一条永远走不通的路上推。
- **识别过的页会被下一次搜索读回来**（`GET /ocr/pages` 一次读整本）：没有这条，「识别这 111 页」只在当次会话有效，关掉书再打开又变回「没有文字层」，用户得再等 90 秒而没人解释为什么。
- **每认出一页就地补进命中列表**：111 页要 70–90 秒，前 10 页就能看到「已找到 2 处」是这个按钮唯一能撑住等待的东西（跑完仍由检索 effect 重跑一遍作为权威结果）。
- 「没有命中」只在**真的按某个词搜过**之后才说 —— 扫描书建索引那一轮一处都没找，说「没有命中」是自己编结论。
- 面板与目录 / 划线 / 伴读**互斥**（中间永远只留一栏）；输入即搜（220ms 去抖），`Esc` 收起。
- **识别结果不只给搜索用**（0.28.0）：同一份 `ocr.json` 也进分段 —— 认完整本之后目录面板会**自动重抽一次**，扫描书从此有章节、能被逐章解读；这是 agent 侧 `book_outline` / `book_chapter` 不再对扫描库全盲的前提

### 划线 / 笔记（0.76.0）

选中一段就能划线、写笔记，锚点是「页号 + 页内字符偏移 + 摘录原文」。

- **正文换了之后自动跟过去**：重新解析过、插入过一页之后，旧偏移会在**全书**里按 `quote` 重新定位，**唯一命中**才改页码与偏移并画出来；找不到或多处命中就如实标成失配、在面板写明原因（「笔记还在」），**绝不悄悄画到别的字上**。
- **只在读的时候投影，不回写磁盘**：写回去等于把「这一版正文下的猜测」固化成事实，还会让 GET 带上写副作用，去和保存划线的那条串行队列抢同一份文件。
- 比较用「去空白字符后的序列」而不是严格相等 —— 存盘前摘录被压过空白，偏移却是未归一化原文的下标，严格相等会把排版松散的书整本误判成失配

### 逐章解读

目录面板里点「**生成解读**」，宿主在后台**逐章**跑，每章生成一段中文说明（`summary` + 3–7 条要点 + 关键概念）。

- **生成跑在宿主、脱离 HTTP 请求**：一本 30 章的书要几分钟，没有哪个浏览器请求会等它 —— 路由只负责「启动 + 立刻返回」，进度靠客户端每 2.5 秒轮询；**关掉面板不会中断**（这条写进了界面文案，不说用户会守着不敢关）。
- **单章失败不拖垮整本**：第 7 章因为一次 429 挂了，8–19 章继续跑完，那一章标「失败」并保留原因（悬停可见），再点一次只重试失败的章。
- **取消不是失败**：点「停止」时正在跑的那一章回到 `pending`，已生成好的一个都不动 —— 标成 failed 会让「已解读 3/19 · 失败 1」凭空多一个失败，而用户只是不想继续了。
- **`skipped` 与 `done` 是两个状态**：卷标题页、版权页、正文不足 200 字的章**不调模型**、标「略过」；把跳过算成完成，「已解读 19/19」就是假话。
- **生成前先报数**：「约 2.5 万字输入 · 3 次调用（最多 6 次，照抄重试会多一次）」—— 只写「可能要一会儿」等于让用户闭眼刷卡。
- **点章节行仍然是跳页**（0.17.0 定下的），「看要点」是行右端**独立的箭头**，两者是兄弟节点不是嵌套（`<button>` 里套 `<button>` 是非法结构，有断言钉着）。
- **只跑勾上的那几章**（0.19.0）：每行前面一个勾选框，「全选 / 全不选」只作用于**这一次待生成的章**；按钮上的章数**来自勾选**（`生成解读（N 章）` / `继续生成（N 章）` / `重新生成（N 章）` 三种文案分开 —— 「重新生成」最贵，用户点「继续」时期待的是补上没做的，结果把花过钱的几章重跑一遍）。**显式勾选会覆盖「已 done 就跳过」**，否则「重新生成（3 章）」是假话；反过来「没带 `chapters` 这个键」与「带了一个空数组」必须分得开（前者 = 老行为，后者 = 调用方 bug、当场抛）。
- **进度分两个口径**：`digestTotal`（全书，驱动「已解读 2/19 章」）与 `digestRunTotal/digestRunDone`（这一批，驱动进度条）—— 合成一个的话，勾 2 章跑完时条子会停在 2/19 一动不动。
- **解读可以单独选模型**：设置项 `digestModel`，**不是**复用翻译那个 `aiModel`（翻译一篇一次、解读一本书几十次调用，用户会给它们用不同的模型）；面板里一个下拉框，选完写回设置，下次打开还是它；每章要点上标出实际用的模型（「模型 free/xxx」），只有用户说得出名字他才敢确认这一章不是默认模型跑的。
- **解读正文不在目录里**（0.19.0）：306px 的栏里塞「总述 + 要点 + 术语」会把目录挤走大半，正文改由 `DigestCard` **浮在阅读区上**；不做第三列是因为那会改变书页区宽度 ⇒ `ResizeObserver` 触发 ⇒ 整页重画一次位图，翻页手感当场变差。浮层挂在 `.npr-book-main`（`position: relative`）上，只盖书页那一格、不压工具栏 —— 基准一旦退回 `.npr-reader`（它本来就有 `position: relative`），`top:10px` 就会压住工具栏，而源码看着完全正常，所以这条有**真几何**判据

### 逐章解读怎么保证不糊弄

**「抄原文」的判据是两条，因为只靠一条会误杀**。实测（4000 字样例章）：完全自述重合 0.00 / 游程 5；**引用原文一句（28 字）重合 0.20 / 游程 27**；**引用两句重合 0.39 / 游程 27**；搬了原文 300 字重合 0.94 / 游程 282。最初只判「重合率 > 0.3」—— 那样**引用两句就会被判成照抄**，而这是正当写法。改成「**最长连续游程 ≥ 60 字**」当主判据（抄一段必然留下长游程，引用一句不会）+「重合率 > 0.6」当副判据（防「把原文拆成很多短碎片重新拼」，这种每段都不长）。**照抄只重试一次**，第二次的提示里写明「最长有 N 个字连续相同、整体重合 X%」（只说「别抄」模型会以为自己在改写）；两次都不行就标失败。

- 模型被要求吐**结构化 JSON**（`{summary, points, terms}`）而不是 Markdown —— 客户端那个 Markdown 渲染器不支持表格、`<ol>` 会变无序列表；结构化之后要点是真 `<ul>`、术语是真 `<dl>`，也才有可断言的形状。模型不肯吐 JSON 时退化成「整段当摘要」并**在界面上说明**，不把已经付过钱的那次调用扔掉

### 导出成技能包

目录面板底部一个**默认折叠**的「导出成技能包」（0.20.0，视觉 0.20.1 重做）：

- **折叠态就要说清点了会得到什么** —— 标题下一行小字「索引 + 每章一份 + 术语表，agent 按需读」，右侧一个 chevron（`<details>` 的默认三角被 `list-style:none` 去掉后，不补就看不出这里能展开）；**展开后副标题自动收起** —— 小窗口 401px 面板里，展开态多这两行会**溢出 25px**、把「已导出 …」那行裁掉（真几何量出来的），而副标题本来就是给「还没点开的人」看的；整块用**品牌色 7% 混色**当底色划出「这一块是动作」（不能用 `--npr-bg-2`：浅色主题下 base/layer-1/2/3 是同一个白，改了等于没改），导出按钮是**实心主按钮**（`--npr-accent-strong` + 白字，和设置页主按钮同一档），不是一圈描边的幽灵按钮。0.20.0 那版被用户一句话否掉：「这个设计的太不明显了」—— 问题不是配色，是**层级反了**。
- **0.24.0 再补三档**：① **入口搬到目录面板里「生成解读」右边**（0.24.1）—— 一颗 `book-to-skill` 按钮。0.24.0 曾把它放进顶部胶囊（「导出」那一格），被用户一句话否掉：「把导出放在菜单条毫无意义」；理由站得住：胶囊那组是**视图开关**（伴读 / 划线 / 配色 / 沉浸），把一个**产出动作**混进去，视觉同级就被读成语义同级，而且它离产出太远 —— 用户刚在面板里看到「已解读 59/59」，手却要回到顶部去点一个跟「划线」平级的开关。现在它就长在那句话旁边；**没有解读时不可点**（技能包的内容就是那些解读，一章都没有时导出只会产出一个空索引），置灰配 `title` 说清为什么。两颗按钮**不同级**：左边是 accent 描边的主按钮（会花钱跑模型），右边是中性细描边的次要动作（纯拼装）。那一颗**不做第二套导出 UI**，它只是摊开导出块、滚进视野并跑一次导出 —— 否则同一个动作会有两处按钮、两套 busy 态、两处会漂移的文案。
- 判据 ㉑ 守「两颗按钮同一排、都在这一排之内、不互相压住」，反向对照就是把 `min-width: 0` 拿掉并换最长文案（`继续生成（120 章 · 46.1 万字）`）：右边那颗被顶到 **335.4**，而这一排的右缘是 **312**（面板右缘 326 里有 14px 内边距）—— 第一版拿面板右缘当阈值，318.4 < 326「通过」了，是一条假绿。
- 判据 ㉒ 守「不可点**看得出来**」：只加 `disabled` 属性不够（本项目记过「缺 `:disabled` 样式 ⇒ 看着能点、点了没反应」），量的是两态 computed style（可点 opacity ≥ 0.95 / 不可点 ≤ 0.7 且 `cursor: not-allowed`），反向对照把灰化盖掉必须变红。② **一键复制完整路径** —— 「已导出 …/skills/book-labc」原来只是纯文本，而下一步必然是 `cp -r` 它。③ **包体积** —— 导出成功后那行小字换成 `SKILL.md 12.4 KB · 24 个文件 · 268 KB · 4.1k 行`，tooltip 里逐文件列出；`SKILL.md` 单独拎出来是因为它**每次都进上下文**，其余文件 agent 只在需要时才读。统计由宿主**现读盘**算（`skillFiles`）⇒ 旧包也有清单，不必为了看一眼体积重新导出；行数口径是「末尾换行不算一行」。
- 统计行**复用**原来那行 hint、不新增一行 —— 展开态在 306px 栏里只剩 ~19px 余量，多一行就把导出按钮顶出面板（0.20.1 已踩过一次）。判据 ⑳ 守「复制按钮整颗在面板内、且不压住路径文字」，反向对照就是把 `min-width: 0` 拿掉（真实错法）：长路径把按钮顶出面板 **121px**，而它仍在 DOM 里、仍能 Tab 到，用户却点不到把一本书的解读**拼装**成 `SKILL.md`（章节目录，常驻上下文）+ `chapters/chNN-*.md`（每章一份，**按需加载**）+ `glossary.md`（跨章术语，标注出现在哪几章）+ `patterns.md` / `cheatsheet.md`（侧写页）+ `skill.json`（机读）。
- **为什么要它**：在此之前解读**只有人读** —— 伴读只看得到当前这一页，解读是唯一「整本书沉淀下来」的东西，却没有任何机器消费者。而 agent 读原书要么 20 章 × 1 万 token 全塞进去、要么根本读不完；有了索引层，一次查询是「1k 索引 + 1k 那一章」。
- **默认不重新调模型**：`SKILL.md` / `chapters/*` / `glossary.md` 全是从**已经付过钱**的解读里确定性拼出来的，导出本身零成本；只有勾了「跨章综合」才多**一次**调用去写 `patterns.md` / `cheatsheet.md`，而且那一次失败也**照样出包**（那两页写成摘录并标 ⚠），不把已经写好的文件扔掉。
- **书型分三档**（技术书 / 小说 / 非虚构）：小说问的是叙述视角与人称、句式节奏与意象密度、母题与物件、伏笔与回收，速查页是人物 / 地点 / 时间线 —— 不是「章节摘要换个文件名」。书型由**密度**判定（每千字代码特征 6 个 / 引号 8 个，只抽前 5 章各 6000 字），**判定依据写进 `SKILL.md`**（「书型依据：代码密度 0.3/千字、引号 2.1/千字，均低于阈值」）—— 猜错了用户能看见、能手动改。
- **写到插件数据目录的 `skills/<slug>/`，不往 `~/.claude/skills` 写**（那是别人的目录）；`slug` 只允许 `[a-z0-9-]`，中文标题一律回退成 `book-<id>` —— 不转拼音，拼错了比不拼更糟。
- **重复导出先清目录**：不清的话上次的 `chapters/ch20.md` 会留在盘上，一个目录里混着两版书

### 书架的「阅读 / 书架」两页

侧栏分两页，**两页职责不同**：**书架**是全部书（2634 本）的**展示**（按分类 / 书名 / 丛书筛），**点书名什么都不发生**；**阅读**是你自己挑进来的书，**点书名就是取书阅读**。

- 书架页**唯一**的动作是右侧的「**+ 阅读**」（把这本书加进「阅读」页，这个动作**就等于订阅** ——「就类似于 RSS 的订阅」）；加进来之后那一格变成**状态标签「已开始阅读」**（是状态，所以渲染成文字而不是按钮 —— 一个点了没反应的按钮就是「看起来像功能」）。
- 阅读页行右侧的按钮**就是点下去会发生的事**，而且**恢复只能点按钮、点行一律没动作**（0.9.4）：未开始 / 在读 = 「**弃读**」（标记弃读，书仍留在阅读页的「弃读」筛下面 —— 以前一点就消失回 2634 本里，很难再找到）；**读完 = 「重新阅读」**（放回「在读」并打开，**进度不清零**）；**弃读 = 「+ 阅读」+「移出」**（「+ 阅读」放回「在读」并打开、进度接着算；最右的「移出」才真正移出回书架，进度也不丢）。
- **「读完」与「弃读」两行都不可点开**：整行压暗，并在元信息行里写明「要再读，点右边的『重新阅读』/『+ 阅读』」—— 只加 `disabled` 是看不出来的（主按钮颜色写死），而把原因只塞进 `title` 也没人看得到（禁用元素读屏器跳过、鼠标事件不派发）。⇒ 于是「点开一本书」在结构上**只有一个入口**，不靠人记得。
- 两枚动作胶囊之间补了 4px（行的 `gap: 2px` 是给「正文↔动作」的，两枚照它摆会粘成一片）—— 这条有真 Chrome 的几何断言守着。
- 状态筛：**阅读**页带「全部 / 在读 / 读完 / 弃读」，**书架**页带「全部 / 已加入阅读（N）」—— 两页筛的是**不同维度**（阅读页筛 `state`：读得怎么样；书架页筛 `added`：在不在阅读列表。书架是全部 2634 本，那里的「未读」等于「全部」）。
- 「在读」= **未开始 + 在读**：进「阅读」页这个动作本身就表示「我要读它」，所以不设独立的「未读」档 —— 徽章上也写「在读 · 未开始」/「在读 · 读到 N / M 页」，「未读」这个字面量在界面上不再出现。
- 加入与阅读状态是**两个维度**：加进来不等于已在读，**移出也不重置进度** —— 否则「手滑移出」就是一次不可逆的进度丢失。
- **分类与排序下拉只在书架页**：阅读页的列表只有两三本，而分类与计数都是**整库**的（实测 8 项、其中 6 项选中必然 0 本）。控件不显示，它对应的 state 也就不再参与筛选与排序 —— 否则会出现「下拉看不见、列表却被一个隐藏条件筛着 / 排着」。
- **搜索框与这两个下拉、以及结果行同在一个块里**（0.9.3 搬到筛选条下面，0.9.5 压成两行）：排成 `搜索框 │ 分类` / `结果行 │ 排序` —— 四件是同一件事（两个输入 + 一个排序 + 它们的结果），分开摆就会被读成互不相干的事。输入**即时**筛选，所以没有「搜索」按钮（放一个点了不改变任何结果的按钮，就是「看起来像功能」）。
- **两条行各自独立**（0.9.6，两条 `flex` 行，不再是网格）：0.9.5 的两列网格里**同一列的格子共用列宽** —— 分类和排序都在右列，排序因此永远缩不到分类之下（分类最长标签「系列丛书全套（1419）」实测要 **147px**）；结果行在左列只分到 **146px** 而它需要 **214px** ⇒ 文字折成两行（用户报的就是这个）。拆成两条独立行后：可伸缩项 `flex: 1 1 0` + **`min-width: 0`**（`flex-basis: 0` 只是不把固有宽度算进基准，`<input>` 的 `size`≈20ch 与状态文字的单行宽仍会通过 `min-width: auto` 顶住），按内容定宽的项 `flex: 0 0 auto`。实测排序 **146 → 78px**（= 它自己需要的宽度）、结果行 **146 → 214px**、整块 **86.4 → 76px**。位置**两页一致**：阅读页每行只剩一个子元素、自然占满整行（0.9.5 为它加的 `.is-single` 塌缩开关随之删掉）—— 只在书架页做成两列的话，同一个输入框会在切页时**变宽变窄**。
- **阅读页每行左侧有封面，状态靠封面上的一枚角标说**（0.45.3，用户原话「阅读选项下可以增加封面图位吗」+「我觉得 A 角标好像醒目一些。C 的话就是还是放在全文字里，很难发现」）：封面 36×54（2:3，复用日记书墙那套 `BookCover` —— 三种来源已在那边收敛过，PDF 那条还带懒加载），角标压在封面右上角、出血 4px，三档靠**明度**分层而不是第四种色相 —— **在读**=强调色实底、**读完**=正文色反白（全套里对比度最高）、**弃读**=中性淡底 + muted 字（语义是「停下了，不是出错」，所以不用红：红在深色界面里读作「出错了」）；三处颜色全从令牌派生，浅色主题下反白关系自动翻转。
- **角标字跟着徽章文字走、不跟 `name` 走**：`unread` 与 `reading` 的徽章都是「在读」，角标也必须同字，否则同一本书「角标说未读、徽章说在读」。
- **终态不在元信息行再说一遍**：加封面吃掉 45px 后，「在读 · 读到 24 / 387 页」会把 `PDF · 7.7 MB` 挤成孤儿行（第二行只剩体积数），所以阅读页徽章只留进度、读完 / 弃读干脆不写 —— 无封面的书架页维持原样，那里徽章是**唯一**说状态的地方。
- **书架页不画封面**：判据放在**页**这一级而不是行这一级，阅读页十几本、书架页 2634 本，每行一张封面等于 2634 个 `/cover/:id` 请求或 2634 次客户端交叉引用解析，成本差三个数量级

### 电子书对照（0.58.0 · 整本 0.61.0 · 语种 0.62.0 · 剩余时间 0.63.0 · 读法 0.65.0）

打开一本**英文 EPUB**，工具条上那颗按钮写着当前读法（**原文 / 对照 / 译文**），点开是三选一：**对照**是每一段原文下面紧跟它的中文译文，**译文**是只看中文（没译到的段落先显示原文，不留白），**原文**是一个请求都不发。

- **为什么是三个档位而不是一颗开关**：开关只能表达「要不要译文」，而「只读译文」跟「只读原文」是两个相反的状态，两态开关表达不了中间那个 —— 用户就只能靠「开了对照再逐段自己忽略原文」来模拟全中文。
- **全中文读的是译文**：划线 / 笔记 / 搜索高亮都锚在原文的字符偏移上，这一档里「划线」「笔记」两颗按钮是灰的（`title` 说清「切到『对照』再划」），复制与问伴读照旧 —— 存一条锚在译文里的划线，回到对照时会把高亮画在原文完全不相干的字上，而且看起来完全正常。读法是**全局偏好**（换书不重置；中文书整颗灰掉、也不改用户的选择），默认「原文」—— 不替用户打开会产生模型费用的形态（MOBI / AZW3 / TXT 同样走这条链路，只要解析出的是块模型）。
- **默认翻到哪译到哪**：按**节**翻译，已译的落盘缓存，翻回上一页是零成本 —— 只想看第 3 章的人不必为整本付钱。
- **整本翻译收在「澄境阅读助手」里**（0.60.0）：入口是**「电子书阅读」页签左栏顶部**那颗图标按钮，**点开是一张居中的窗口**，列出「在读」里的电子书，一本一行 —— 书名 + 扩展名 tag + `已译 6 / 14 节 · 还剩约 8 分钟 · 第 7 节 · 382 KB` + 进度条 + 右侧一颗 `翻译全本`（在跑的那本写 `翻译中`、停下过的写 `继续`、译完的写 `已译完`）。
- **只在「在读」页签可用**，其它页签里它变灰、`title` 说清为什么（灰化态连 hover 都不亮）—— 它回答的是「哪几本在读的书还没译好」，这是书架层的问题，不是「我现在就读这一段」；藏起来等于每次都要人猜这功能是不是没了。
- **不占工具条**：那排是「对这一段做什么」，随百分比左右挪的按钮最耗注意力，而整本翻译是几十分钟、跨书跨页的事。
- **窗口关得掉，任务关不掉**：翻译在宿主侧跑、进度写在磁盘上，关窗只是收起列表，左栏那颗按钮上仍有一颗在走的小点，下次打开接着看。
- **一本一行，行里三件事**（0.61.0）：**封面**（复用书架那颗 `BookCover` —— EPUB 与 MOBI / AZW / AZW3 都用书里那张真封面（0.71.6 起 MOBI 系的 EXTH 201 也解了）、PDF 渲染首页、都没有时按书名哈希生成底色，所以同一本书在两处长得一样）、`正在翻译 · 17% · 还剩约 2.3 小时`、右侧一颗按钮（`翻译全本` / `翻译中` / `继续` / `已译完`）。百分比与剩余时间**都来自宿主**（进度以磁盘为准，ETA 是最近 5 节实测耗时 × 剩余节数），「第 7 节 / 共 14 节」这类中间量放 `title` 里。
- **剩余时间跨会话活着**（0.63.0）：每节实测毫秒数落盘在 `prefetch-stats/`，所以「昨天译到 17% 停下、今天点继续」**一开跑就有「还剩约 2.3 小时」** —— 不然百分比在（磁盘的结论）、时间却空着（内存的结论），正是用户截图里那个样子。第一次翻这本书（没有历史样本）时说「正在估算剩余时间」，第一节跑完就给数；**不拿字符数估假数字**，因为那个数会在第一节后突然腰斩，而人记住的是第一个数。
- **多本可以同时翻**（0.61.0 推翻 0.59.0 的「同时只跑一本」）：每个任务内部本来就是**逐节串行**，并行 N 本 = 同时在飞 N 个请求，不是 2N 倍；上限 `DEFAULT_MAX_CONCURRENT = 4`（管的是内存 —— 每个任务持有一份整本解析结果），超了**明确报错**、不偷偷排队。多本在跑时底栏那颗「停止」变成「全部停止」。
- **只列正文是外文的书**（0.61.0 加，**0.62.0 修对判据**）：判据是宿主的 `script` —— 解析整本时按**字符量**算汉字占比，≥ 0.7 记 `zh`（实测纯中文书 0.93–0.98、纯英文书 0.000、中英双语排版 ≈ 0.5，所以 0.7 既判得干脆又**不把双语版误判成中文**）。
- 0.61.0 曾用 `total === 0` 反推，那是错的：「可翻块」是**逐块**判的，中文段落里夹一串英文人名（「这些人包括 PaulHodges」）就会被判成该翻，一本纯中文书因此有几节可翻、照常进了列表（实测《越红钩》107 节里 8 节中招）。字母不足 200 不表态（`unknown` 按「可能得翻」处理），**探测失败则保留** —— 未知不等于「中文」。中文书连**宿主 `start`** 都拒（`EBOOK_PREFETCH_CHINESE`），不只是界面上不列。
- **同一条判据也管「对照」**：中文书里那颗「对照」是灰的（`title` 说「这本书的正文是中文，不需要中英对照」）—— 它的每一节结论都一样，点开只是把「这本书不用翻」复述一遍。判据是整本的，所以英文书里夹一节中文引文时「对照」仍然能用。译完的条目 12 秒后自己退场；**停 / 中断的留着**，因为那是要接着处理的两种状态。进度和剩余时间是**实测**的（每节真实耗时 × 剩余节数），不是抓模型日志里的进度串——那种正则一换模型就静默失效。分母是「**有可翻文字的节**」（纯中文节、只有代码的节不算），失败的那几节**不计入进度**，所以进度条不会在缺两节时假装 100%。
- **可随时停**：已译的节留在磁盘上，再点就是接着翻；同一节被预翻和翻页同时要也只调一次模型。**正在停止**的那一两秒界面明说「正在停止」—— 宿主收尾期间它还会老实回答「在跑」，照单全收会让按钮跳回「正在翻译」，用户以为没点上。
- **不需要对齐算法**：电子书正文本来就是块（`{k, x}`），译文按**块下标**贴回原位，跳过代码块 / 空块不会让后面的译文前移一格。
- **什么不翻**：`pre`（代码与诗歌的缩进翻不得）、已经是中文的段落（双语书不该把中文再译一遍）、没有字母的块（页码、分隔线）。
- **失败与缺段都说出口**：正在翻、这一节没有英文、本节 18 段译出 15 段、失败原因 + 重试 —— 只显示「成功」的话，用户看到中英混排会以为插件坏了。

## 翻译与对照

### 中文版本

原文、**译文**、**改写**三种视图。译文与改写由模型生成，缓存进本地数据。**保结构翻译**（0.13.0）：译文只换文字，链接 / 图片 / class / 布局一个标签都不动 —— 先收集文本节点、把纯文本清单发给模型、再按编号写回原 HTML 位置。旧路径（Markdown 中转）仍用于改写。**原文插图原样保留**：提示词要求 + 生成后按**图片身份**（URL 末段路径，转换参数不参与）核对 —— 抄错参数的 URL 换回原文那一份、真缺的补回一张

### 双语对照（0.57.0）

版本下拉里多一项「**对照**」：**逐段交错** —— 每个原文块后面紧跟它的译文块，同一屏就能核对一句译得对不对（此前只能在「原文 / 译文」之间来回切，切一次丢一次位置）。

- **不需要对齐算法**：保结构译文只换文本节点、标签一个不动 ⇒ 两份 HTML 逐元素同构，第 N 个 `<p>` 天然对第 N 个 `<p>`。
- **对不上就不对齐**：0.13.0 之前生成的旧译文走 Markdown 往返、结构早已不同 ⇒ 整篇退成「上原文、下译文」，并在正文上方**如实说明**（塞错位置的译文比没译文难发现得多）。
- **容器不复制**：`<li>` / `<td>` / `<th>` 的译文插在元素内部 —— 整体复制 `<li>` 会让有序列表变成 1,2,3,4。
- **图片与代码不复制**：副本里的 `img/picture/video` 全摘掉，`pre` 整段跳过；副本也**不带 `id`**（两个同名锚点会让目录跳转与高亮错位）。
- 没有译文时下拉里**不出现**对照；「重新生成」在对照视图下落回译文（没有「生成对照」这条路径）。

### 选翻译模型

翻译 / 改写可以**单独指定模型**（设置 → 阅读体验 → AI 补全阅读版本），不动 Harness 的默认模型。翻译量大、重复、不需要很强的模型 —— 压到一个便宜的或免费的模型上是合理需求。下拉框列出 Harness 里注册的全部 provider 与模型；留空即跟随默认。**免费模型从哪来**：Harness →「设置 → 模型」→「添加模型提供商」→「自定义模型 API」，填一个 OpenAI / Anthropic 兼容的端点（中转站、自部署服务、免费额度服务都行）即可，之后这里就能选到。

- **电子书解读有自己的一项**（0.19.0，`digestModel`）：目录面板里直接选，选完写回设置、下次打开还是它。**不复用翻译那个 `aiModel`** —— 翻译是一篇一次、解读是一本书几十次调用，两者会想用不同的模型；共用一个键意味着「给解读换个免费模型」会顺手把翻译也换掉。两个键走同一个校验判据，留空都是「跟随 Harness 默认」

### 英翻中

**英文原文自动翻译成中文**（设置页可开关，默认关）。打开后，打开一篇英文原文的文章就**直接在阅读区显示中文版本** —— 不需要在 AI 伴读框里打 prompt。语种由汉字占比判定（先剥 HTML 标签），中文原文不动、日文/韩文不翻、样本不足不猜

### 侧栏统一与翻译双模式（0.71.0）

**四个模块的左侧栏用同一份宽度**：订阅 / 书架 / 论文 / 日记共用 `src/client/sidebar-width.js`（默认 340px、下限 256、上限 520、同一个 `npr.sidebarWidth` 键），旧 RSS 的 `npr.listWidth` 自动迁移，论文页那条分隔条从装饰改成**真能拖**、双击复位也对齐同一个基准。

- **翻译两颗并一颗**：顶部胶囊只留一颗「**翻译**」下拉，三条途径都在菜单里 —— 「翻译本页」（逐页按需，翻过就直接读本机缓存）、「翻译全本 · 继续翻译 · 停止翻译 · 全本完成可重跑」（整本一次翻完）、「清除译文」（二次确认）。「看原文 / 看中文」不在这颗菜单里：它是工具栏那颗 **中/英**，一次点击就切，菜单只留会调模型的动作。
- **两条路共用一份页级译文缓存**：逐页翻过的页整本模式会跳过，整本跑出来的译文逐页阅读也直接命中；译文按 `page-translations/<bookId>/p<page>.json` **一页一个文件**落盘，重开插件不必重新花钱调模型，分段规则或原文变了自动作废重翻。落盘失败只影响「下次重开」，当前这页照常显示，并且**会提示一次**（0.71.3 之前这里是哑失败：段落 id 带冒号被落盘校验全丢，缓存一页都没写成，界面上却毫无迹象）；整本任务可停止、停过或失败后再点只补未译页、连续 3 页失败自动中断。
- 阅读器只订阅任务的**状态字符串**，逐页进度交给独立小组件订阅 —— 否则整本跑几百页会把整棵阅读器重渲染几百次

## 日记与灵感

### 日记（第三个 tab）

顶部「订阅 / 书 / 日记」三选一。**Obsidian 风格的 Markdown，一天一篇**，存在**插件自己的目录**里（`~/.dsh/storages/dsh-npie-reader/diary/daily/YYYY-MM-DD.md`）—— 与你的 Obsidian 库**零耦合**，不会往 `Daily/` 里写东西。

- **日记内部按三个功能模块组织**（不是「条目类型」）：**灵感速记**（一个输入框打开即写 + **标签云** + **一条按时间的时间轴**（标题叫**你的灵感时间线**，打开就展开今天，条目分两层 —— 首句当**加粗标题**、余下当淡色摘要，不再是一行截断的灰字）：RSS 里按 `L` 记的、书里按 `L` 记的、灵感页手记的**全排在这一条上**，靠条目头的 **chip** 区分来源 —— 书暖褐 / 文章蓝 / 手记没有 chip。**「这本书 / 这篇文章的全部灵感」不是另一个选项卡**，而是这条时间轴的**一次收窄**：入口在出处卡片里，出口是顶上那条带 ✕ 的横条）
- **便签墙**（0.64.0）：灵感模块的正文区是一面纸片墙 —— 顶上第一张是**可写、可选六种纸色的便签卡**（右下角一枚「贴到墙上」），下面按**最新在最前**铺三列（窗口窄了自动两列 / 一列）。每张只露**六行**，卡顶是正文里的**第一个 `#标签`**（没写标签就不占那一行），卡底是时间与展开，**删除与出处只在鼠标指上去时出现**（常驻一颗垃圾桶，纸片就成了待办）。
- 纸色**只存色名**（`meta.tone` = amber / rose / sky / mint / lilac / cream）不存十六进制：颜色要跟着深浅主题混出来，存死一个 `#fbe3a1` 在深色界面里就是一块自发光的板子。老条目没有这个字段时**按条目的键算一个色**（不按「第几条」轮发）—— 删掉一条邻居，整面墙的颜色不会重新洗牌。
- 只有灵感模块铺墙：私密要「默认不渲染正文」、读后感是连成一篇的长文，两者都不动（那两处仍是原来的流水行）。· **私密日记**（加密输入 + 情绪 + 日历）· **读后感**（选**一本已标记「读完」的**书 —— 侧栏分「读完的 / 还没读完」两组，没读完的整组灰掉、写着「未读完」、点不动，阅读器里那颗按钮也是禁用的 + **书籍档案卡**（划线 / 摘录笔记 / 读后感 / 字数 / 读到，五个数全部来自已有计量，**没有**「阅读时长」那一格 —— 插件不计时，不编数）+ 结构化模板 + 这本书的划线侧栏，点「引用」把金句插进正文）。条目仍是一行 `## HH:MM 类型 · 来源`，但**类型由模块决定**，不用手选。
- **只追加**：写新条目是字符串拼接，旧内容逐字节保留（连你自己手改过的格式也不会被重排）。
- **情绪五档**（😄🙂😐😣😔，每档带中文名、选中按档染色；老数据里的 `😕` 读回来自动换成 `😣`）写进标题行下方的 HTML 注释，Obsidian 看不见、纯文本可见；日历上有心情的那天上色。
- **私密条目**落进 `private/YYYY-MM-DD.md.enc`（AES-256-GCM，密钥在登录钥匙串；不可用时退回 0600 文件并**如实告诉你**），灵感 / 读后感仍是明文。
- **正文里写 `#标签` 就自动归类**，点标签=搜它。搜一句能跨天找（`GET /search`）。**AI 整理这一天**：日期栏上一颗按钮（**不是**每条记录一颗），新开一个 Harness 会话、把**这一天**的日记当引用材料带进去（从第 1 条起，40 条 / 24000 字封顶 —— 不是只看前几条），整理稿由模型用 `diary_append` 追加成**新的一条**，原文一个字不动 —— 权限在工具层就锁死了（只有 append，没有改写 / 删除）。导出全部是一个**单文件** Markdown（每块前一行 `<!-- name -->`），避免浏览器把多文件下载全拦下来；**默认不含私密**，含私密要连点两次。
- **顶部那四颗工具跟着当前模块走**（0.86.0）：搜索只搜这一块、导出只导这一块（文件名分别是 `灵感速记-导出-…` / `读后感-导出-…` / `私密日记-导出-…`，私密走两次确认）、垃圾桶只在灵感模块出现（贴图入口只在那儿）；文件夹按模块分到 `private/` 或 `daily/` 并选中最近一天 —— **灵感与读后感同处一个 `.md`**，所以这两档是同一个目录，差别在选中哪一份，界面文案如实写明。不带 `module` 的调用（agent 工具、老客户端）仍然是「全部且逐字节可逆」的老口径

### 灵感速记（`L`）

读 RSS 或电子书时按 **`L`**，浮层里**只有一个输入框**（没有类型、没有情绪、没有私密开关 —— 那些在日记页对应模块里），`⌘/Ctrl + Enter` 保存、`Esc` 关闭、打开即聚焦，存进**今天**的「灵感」。

- **写完那一刻可逆**（0.72.0）：回执是「已记下 · 今天第 N 条 · 挂在《…》上」+ 两颗按钮（**撤销** / **去看看**）；N 与日记页顶栏**同口径**（排除读后感，所以不是 `index + 1`）。撤销前会先读回今天、按 `scope + index` 核对正文是不是自己刚写的那句 —— 只按序号删，会在「用户先删了上面一条」时删掉另一条记录，核对不上就只给「去看看」。
- **关掉不再连草稿一起丢**：没写完的半句留 24 小时，下次按 `L` 填回来并**明说是哪来的**（「已恢复 09:12 未写完的内容（原来记到 《某本书》· 第 2 章）」+ 一颗「清空」）；草稿连同**来源**一起存 —— 在《A 书》没写完的句子不会挂到《B 书》上，空的不算草稿，坏数据当没有且读不删。
- **带选区进来**（0.72.0）：正文里**先选中一段再按 `L`**，框里是一段 `> 引用` + 一个空行、光标落在引用之后。与「摘录到灵感」**分工**：那颗按钮是不编辑直接存（`source` 标「摘录」），`L` 是带进来接着写（`source` 仍是书名 / 文章名，所以**不**标「摘录」）。引用截到 500 字（一次全选可以是整章）；每行加 `> ` 还顺手避开一个隐患 —— 引文里原本的 `## 12:00 灵感` 不再出现在行首，宿主不会把它切成第二条日记。有未写完的草稿时草稿优先，提示行会明说「选中的文字这次没带入」。
- **`#标签` 在浮层里可补全**（0.72.0）：敲 `#` 出现最近用过的 6 个（与 `/tags` 同源、按最后使用日期倒序），`Tab` 补上、`↑` `↓` 换、`Esc` **先收候选**再关浮层；`C#` 与 URL 里的 `#anchor` 不弹候选，中文输入法组字期间不拦键盘（`isComposing` / `keyCode 229`）。
- **可以直接贴截图**（0.73.0）：在框里 `⌘/Ctrl + V`，图落到 `diary/assets/`，正文里留下一条 `![](…/diary/assets/<内容哈希>.png)`，日记页与便签墙上**当场显示得出图**（正文渲染本来就是 markdown → sanitize，`img` 一直在白名单里）。收 PNG / JPEG / GIF / WebP、单张 ≤ 8 MB；**SVG 不收**（它是 XML，能带脚本）。
- 用粘贴而不是加一颗「选图」按钮：截完图的手指本来就停在 `⌘V` 上，多一颗按钮就多一次点击，而速记的价值全在「不漏那一次」。
- 名字是**内容哈希**（同一张图贴十次只占一份；名字里没有用户输入，所以路径穿越在入口就被白名单挡掉），类型按 **magic bytes** 判（不信浏览器报的 `content-type`）。
- **图还在路上时不许保存** —— 否则存下的是一条指向不存在文件的空图，而回执照样说「已记下」；连贴两张时按**张数**算，第一张落地不会解锁保存（0.73.1）。
- 大图会**缩到纸宽**显示（正文与便签墙各一档，三行截断时给固定高度），不会把那张纸撑到图的原生宽度。
- 贴过的图可以清理（日记页顶栏那颗垃圾桶，**先报数再删**）：只删「没有任何公开日记正文引用、且落盘超过 7 天」的图 —— 7 天是为了不误删草稿里那张（草稿在浏览器里，宿主看不见）；私密日记的正文是加密的、核对不到，所以预演时会明说这一点。
- 订阅页与书架**共用一份**浮层；日记页不响应 `L`（那儿本来就有输入框）。
- **灵感流转**：在书里按 `L` 时，正在读的**书 / 页 / 章**自动写进 `meta`（`book` / `page` / `chapter`），浮层里多一行**纯文本**「会记到 《书名》· 第 N 章」——那行不是控件，浮层里仍然只有一个输入框；离开书架时上下文清空（否则切回订阅页记的灵感会被挂到上一本书上）。
- **出处 chip**（0.47，替代 0.46 那颗 13px 图标）：读过的东西里记下的灵感，条目头上是**带字**的一枚 chip（书 `book-open` + 《书名》暖褐 / 文章 `file-text` + 标题蓝），点开是一张 **300px 卡片 —— 封面、它是什么（第几章第几页 / 哪个频道谁写的什么时候发的）、什么时间在这条来源下记的、一段摘要，以及「打开这本书 / 跳到这篇文章」和「这本书的全部灵感 · N 条」**；卡片里的文章信息走宿主新加的只读方法 `entryMeta()`（**不**去原文页抓正文，离线也画得出来）；**在灵感页手记的那条没有出处，就什么都不长** —— 「挂到书上」那个事后手工挂载的入口已经删掉，出处只来自「读的时候按 `L`」

### 从书里写读后感

PDF 与电子书的顶部胶囊各多一颗「写读后感」：带着**这本书**跳到日记 tab 的读后感模块，书名已选好、模板已预填。

- **只有标记为「读完」的书才点得动**（没读完是 `disabled`，`title` 写着「标记读完才能写读后感」）—— 读后感是对一本书的收尾，不是边读边记。
- 书里**没有**第二个输入框 —— 读后感只有一条写入口（`日记/*.md`），两条路早晚漂开。
- 书不在书单里也能跳（书架会被 `BOOKS_PAGE_LIMIT` 截断，`GET /book/:id` 只认 id）

### 论文（第四个 tab，0.68.0）

顶部「订阅 / 书 / 论文 / 日记」四选一。按 **arXiv 编号 / DOI / 标题**导入，或直接上传本地 PDF；开放获取的**自动补下载全文**（元数据三级源：arXiv Atom → Crossref → OpenAlex；全文地址取 OpenAlex 的 `best_oa_location.pdf_url`，付费墙内的给 DOI 落地页并提示手动上传）。**速读卡**给标题 / 作者 / venue / 摘要 / 标签 / 进度 —— 先决定要不要读，再打开正文。

- **PDF 落盘之后就是一个普通 PDF 书条目**（宿主 `paperAsBook()` 造条目），所以目录、找词、划词、划线、逐章解读、读后感全部**原样复用书架那条链路**，一行阅读器代码都没改。
- 移入回收站可恢复，**彻底删除才连 PDF 一起删**；回收站里的条目只允许彻底删除，库里的只允许移入回收站。
- **状态标签与书架同一套**（0.77.2）：徽章一句话说完「在读 · 3/33 页」（一次没翻过写「在读 · 未开始」），筛选只有 全部 / 在读 / 读完 三格 —— 「在读」**包含刚导入、还没打开过的**（`status: new`），库里不再出现「未读」这个词；读数行是「筛出 / 总数 · 在读 N · 读完 N」。
- **读完的论文整行点不动、灰掉**：那一行 `disabled` + 压暗，唯一入口是右侧那颗「重新阅读」（速读卡主按钮同款），点了才放回「在读」，而且**不清零进度** —— 打开就停在上次那一页；「在读」的论文点开同样是续读，不再从第 1 页开始。
- 选中的那一条**一眼看得出来**（强调色底 + 描边 + 左侧 3px 竖条，标题转强调色），不再与 `:hover` 的浅灰混成一个样子。
- 两处例外是为了不留「点了没有任何事」的死行：回收站里的条目恒可点（要选中才能恢复），读完但**没有本地全文**的也可点（它没有正文可开、也就没有「重新阅读」，锁死连摘要都看不到）

### 页内链接与划词翻译（0.68.0）

**页内链接**：PDF 里指向参考文献编号 / DOI / 目录的内部链接真的能点 —— 外链开浏览器、内部目的地解析成页码后跳过去（内置 pdf.js 6.4.299 **没有**默认 `LinkService`，这一层是自己接的）。只放行 `http` / `https` / `mailto`，`javascript:` / `file:` / `data:` 一律拦下。**划词翻译**：选中一段，气泡上的「翻译」用 **dsh 里配置的模型**翻成中文，译文落在书页底部的独立浮层（不随选区消失，可复制；公式与模型名保留原文）

### 论文引用与 Agent 工具（0.69.0）

**复制引用**：速读卡上「复制引用」生成一段能直接贴进 `.bib` 的 BibTeX（双层花括号保大写、特殊字符转义、引用键去重，全部由 `src/paper-bibtex.js` **一份**实现）；剪贴板被拒时把文本摊在卡片里手动选。**补全元数据**：拿 DOI / arXiv 编号再去 Crossref / arXiv 查一次，**只填空着的字段**，已有的标题摘要绝不覆盖；查不到不是错误。**5 个 `paper_*` 工具**：`paper_list` 列本地库（按标签 / 状态 / 词筛）· `paper_search` 在标题 / 摘要 / 笔记 / 标签里全文找词并给命中片段 · `paper_import` 按编号 / DOI / 标题导入 · `paper_abstract` 读单篇摘要 · `paper_related` 按标签 / 分类 / venue / 作者找相关论文。

### 页级按需全文翻译（0.70.0 · 0.71.3）

顶部胶囊两颗：**中/英** 一键在译文与原文之间切（纯视图切换，不调模型），**翻译** 下拉里两条途径：**翻译本页**（用 **dsh 里配置的模型**把这一页的英文段落逐段换成中文）、**翻译全本**（后台逐页跑，可停可续，已译页读缓存）。白底盖住原文框、中文铺回原位，**公式 / 图 / 表格 / 版面保留**（画布不重画）。译文按页落盘缓存，翻回来秒开、**重开插件也不用重新翻译**（菜单里会写明「本机已存 N 页译文」），缩放只重排不重新调模型。

- 段落带 id、译文严格按 id 对齐（错配比漏翻严重得多）；整页一次交模型，不是一段一次请求。排版算法移植自 agentero motif（**MIT**，许可见 `src/client/paper-reflow/MOTIF-LICENSE.txt`）。
- **放不下就不画**：上游 `page-overlay.tsx` 是 `filter(p => p.fits)` —— 中文在某个原文框里排不下时，那一段**整段保留原文**，绝不溢出到下一段（0.71.1 曾把框内交给浏览器流式排版，浏览器断行时没人判断放不放得下，于是两段中文叠在一起；0.71.2 改回逐字定位）。
- 作者区的上标（`Haoyu Lu*¹`）按垂直中心挂回它所属的那一行，段框互斥（重叠 > 15% 的后一段让位），居中标题逐行居中。
- **不翻的**：已经是中文的段、字号 < 6pt 的图内标签（整页图会直接显示「这一页没有需要翻译的文字」）。公式 / TeX / URL / DOI / 引用编号先由 `translation-mask.js` 换成占位符，回来逐段还原，丢一个就保留原文。已知边界：pdf.js 6 取不回字体身份，做不到上游「把公式从页面裁图按原尺寸贴回」，保住的是公式不被翻译 / 改写、编号不串位；表格单元格会被当成正文翻。
- **点了之后看得见**（0.78.0）：翻译中那颗「翻译这一页」**变灰不可点**（判据是模块级任务态，与阅读区正中那颗胶囊共用一份 —— 以前菜单不知道翻译已经开始，再点一次什么都不会发生，用户会当成点坏了）；状态胶囊是一条**不确定态**进度条 + 已等待秒数。它**不给百分比**：一页只发一次模型请求，模型不回流中途进度，任何数字都是编的；条上任何一帧都保留 ≥18% 的可见亮条、右端渐隐（假进度最坏的形态不是不动，而是看着像真的百分比）。
- **胶囊钉在阅读区正中，而且真的能停**（0.78.0 → 0.78.1）：翻到长页时它必须仍在视线里，所以从底部挪到正中间；0.78.1 再进一步 —— 它现在画在 `.npr-book-pins`（书页滚动容器的**兄弟**，不滚动）上，**页面滚到哪儿它都在正中**，不再是「这一页的正中」（页面比窗口高时，上一版会跟着滚出视野，等两分钟看不到任何进度）；三个按钮各有明确后果 —— **暂停**是真的掐断请求（`AbortController` 从 `jsonRequest` 传到 `postTranslatePage`），并且**故意不保存半成品**（半页译文混着原文看起来像「翻完了」，比没翻更糟，文案直说「不存到本机」）、**重试**（暂停或失败后才出现）、**关闭**（跑着时先掐断再收起，不留后台还在烧模型的孤儿任务）。
- **一页不再等 168 秒**（0.78.0）：分批改成最多 **2 路并发**（串行跑等于把「翻不完」换成「等不起」），每批完成就**当场回填重画**这一页 —— 读到中文的时间从「最慢那批」提前到「最快那批」。
- **整本要让用户知情**（0.78.0）：点「翻译全本」先弹确认卡 —— 总页数 / 已有译文 / 本次要翻、**时长区间**（跑过的书用实测速率，没跑过的按每页 15–90 秒估 —— 上限按用户实测的 168 秒/页调过，宁可先说长，并在小字里写明是哪一种）、三条后果（后台跑、随时能停、每页一次模型调用）。整本进度条是**真实百分比**并显示「还剩约 N 分钟」；失败或停止后那条胶囊给**收起**（只收提示，不删译文、不丢已译页数与实测速率）。
