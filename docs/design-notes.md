# 设计笔记：已修正的缺陷

> 每一条都是真实踩过的坑，含现象、根因、修法与守卫用例。**改动这些模块前先读这里**。

---

以下缺陷在实现里已修复，每条都有回归用例：

- ★★ **MOBI 的 `textLength` 被无条件采信 —— 一个坏值就能把后半本静默截掉**（0.76.0）。
  正文解压后直接 `.subarray(0, textLength)`，而这个字段本身没被校验过：比实际小就截断
  （用户看到的是「这本书只有一半」），比实际大则无影响（所以测不出来）。现在的判据是
  两道：**① 解出的正文不能是二进制**（JPEG / PNG 魔数、控制字符占比），**② `textLength`
  只有落在「不大于解出的长度、且不是小得离谱」这个区间才采信**，否则整段保留并记一条
  警告。判据写成「坏值与正常值两组 fixture 只差一个声明值，抽出的正文必须**逐字相同**」——
  只断「字数大于 100」的话，截掉 90% 也能过。
- ★★ **带 DRM 的 EPUB 被报成「缺 container.xml」**（0.76.0）。`container.xml` 明明在，
  只是里面的 rootfile 解不开；用户拿到的提示会让他去重新下载一本**根本没坏**的书。
  现在先读 `META-INF/encryption.xml`：只有**真正加密正文**才报 DRM，字体混淆
  （IDPF / Adobe 那两种标准算法）走白名单放行 —— 那是防盗字体，不影响阅读。
  容器缺失的文案也分了三级（没有这个文件 / 有文件但读不出 rootfile / rootfile 指向的
  OPF 不存在），因为这三件事的自救办法不一样。
- ★★ **划线「重排后能找回」只是注释里的承诺**（0.76.0）。存储层写着「文字层变了还能用
  `quote` 兜底找回或如实标为失配」，但全 `src/` 此前只有这句注释、**零实现** ——
  正文重切一次页，旧偏移就画到别的字上，而界面上看不出任何异常。现在按「唯一命中才改、
  否则标失配并说明」执行，失配的划线**不画到任何字上**、也不拦用户重新划线。

- ★★ **长文「译成中文」整篇塞进一次请求 —— 要么转很久、要么直接失败，而钱已经花了**（0.25.10）。
  保结构翻译的链路是「逐段编号 → 模型回编号 → 按 id 回填」，但实现上**整篇一次请求**：
  实测一篇 175,002 字符的正文，prompt 是 175,278 字符 ≈ **7.3 万 token**。
  改成分段（`planTranslationChunks()`，按 12000 字符 / 120 条双预算切，同一段话优先不切开）
  之后是 **14 批 × 12,024–15,109 字符**，41 段一条不丢。
  ★ 分段最容易错的地方不是切、是「切完还对不回原位」—— 这里**没有重编号**（`segment.id`
  仍是全局连续编号），所以回填那条链路一个字没改。★ 上文按**字符**带而不是按条数带：
  第一版「带上 3 条」，实测每批正文 12,024 字符、上文 12,072 字符（「一条 = 一整段」
  很常见），预算凭空翻倍。★ 第一批失败立刻抛 —— 第一批就失败通常是 key / 余额 / 网络，
  继续跑后面的批次只是重复计费。漏翻的段落保留原文，并由界面明说「只翻了 N/M 段」——
  `coverage` 早就算出来了，此前在 `src/client` 里**零命中**，用户看到中英混排只会以为
  「翻译质量差」。
- ★★ **打开任何一本书都是「阅读器页面加载失败 / Cannot access 'toggleImmersive'
  before initialization」**（0.21.0）。`cycleTint` / `toggleImmersive` 两个 `useCallback`
  写在键盘那个 `useEffect` **下面**，而 effect 的依赖数组点在它们的名字上 ——
  依赖数组是**渲染期**求值的普通表达式，此刻 `const` 还在 TDZ 里 ⇒ `ReferenceError`
  ⇒ Error Boundary 接住 ⇒ 整页白屏。上移到 effect 之前即可，真正的问题是**为什么
  测试没拦住**：当时浏览器半区的守卫用桩 React（只验模块体能跑完），其余断言都在读
  源码字符串，而「声明顺序」在字符串层面完全合法。⇒ 新增 `test/book-hooks-render.test.mjs`
  真渲染一次 `BookReader`，并配一条反向对照（同样的写法必须抛 `before initialization`）。
- ★★ **全部解读完之后，「全选」亮着但点了没反应；勾选框看着像消失了**（0.20.6）。
  两个缺陷叠在同一处。① 禁用判据写成 `allTodoPicked = todoN.length > 0 && …`：
  整本都 done 时 `todoN` 是空集 ⇒ 恒为 `false` ⇒ 按钮始终可点，而点击执行的是
  「把勾选设成 `todoN`」= 空集 ⇒ 界面没有任何变化。现在单独判 `hasTodo`，
  没有待生成的章就灰掉，并用 `title` 说明「要重做哪一章，直接勾它」。
  ② 勾选框**一直渲染着**（`<input type="checkbox" class="npr-digest-check">`），
  只是原生 13px 浅灰方框压在浅灰底上看不见。它不能删：解读完之后勾它是重做单章的
  **唯一入口**，于是改成自绘方框（深色描边 / 实心强调色 + 白勾），
  并把误导性的「已选 0 章」在全 done 时换成「全部 N 章已解读」。
- ★★ **翻译后链接丢失、排版格式与原文不同**（0.13.0）。
  旧路径是「HTML → Markdown → 模型 → Markdown → 渲染」的有损往返：
  `htmlToText({links})` 把 `<a href=X>文字</a>` 压成 `[文字]({{L0}})`，模型经常把方括号丢掉 ⇒
  `restoreLinks` 无占位符可换 ⇒ 链接**静默消失**；`markdownToHtml` 只输出裸标签，
  没有 class / 尺寸 / 布局容器 ⇒ 排版必然与原文不同；`sanitizeHtml` 对已转义的 `&`
  不幂等 ⇒ 每过一次多一层 `&amp;`。
  新路径「保结构翻译」把「翻译」和「标记」分开：只收集文本节点、把纯文本清单发给模型、
  按编号写回原 HTML 位置。链接 / 图片 / 布局全部原样保留，因为**它们从没离开过 HTML**。
  真机 53 篇实测：旧路径 36 篇合计丢 8465 个标签、多篇链接 70→0；新路径全部相等。
- ★★ **「更多操作」里那两条跑一会儿的条目点下去没有任何反馈**（0.12.2）。
  「抓取原文全文」要真去原文页抓（几秒到十几秒），「重新加载文章」要重读一遍 ——
  以前点下去菜单立刻关掉、正文没变化，**界面一动不动**，用户只能重开菜单再点一次，
  于是同一篇被同时抓两次。现在操作期间这两条各自 `disabled`、文案改成
  「正在抓取原文全文…」/「正在重新加载文章…」，完成后（含**抛错**）`finally` 复位。
  ★ 两条**各自独立**：一条在跑不影响另一条。★ 除 `state` 外还挂了一对 `ref` 镜像 ——
  `disabled` 只挡得住「重开菜单之后再点」，**同一次快速双击**的第二下可能落在 DOM
  还没更新的那一帧上。
- ★★ **这两条在译文 / 改写视图下没有意义却照常出现**（0.12.2）。
  「抓取原文全文」补的是**原文正文**，「重新加载文章」重读的也是**原文那一份**。
  现在只在「原文」版本下渲染（判据抽成纯函数 `menuItemVisibility({ active })`），
  反过来「重新生成 X」只在非原文时出现 ⇒ 三条**互补**。★ `undefined` / 未知取值
  一律算非原文 —— 宁可少一条，也不要在版本还没解析出来的时候冒出一条
  「点了不知道会发生什么」的条目。
- ★ **「重新加载文章」会把视图跳走**（0.12.2）。它以前调 `openArticle(key)`（**不传版本**），
  `resolveReadingVersion` 于是退回 `reading.defaultVersion` —— 在「原文」视图里点它，
  只要设置里的默认版本是译文，视图就跳到译文去了。现在传 `active`。
- ★★ **部分站点（如 `The Rundown AI`）永远只显示摘要，抓到了原文也抽不出正文**（0.12.1）。
  用户报「插件加载的这个 newsletter 为什么只显示摘要」。根因在 `fulltext.js` 的
  `stripNoise()`：它用 `element.start - (element.tag.length + 2)` **反推**删除起点，
  等于假设开标签写成 `<tag>`（**不带属性**）。真机上是
  `<nav class="text-xs text-mute">` —— 属性比标签名长得多，反推出的起点落在
  **属性值内部**，删完还剩半截 `<nav class="text-xs text-m`（引号不平衡、`>` 已被删掉）。
  那半截标签在下游 `sanitizeHtml` 里被 `findTagEnd` 的引号跟踪吞掉 **931 字符**。
  ★ 整条链的实测：抓取 200 → 抽取成功（容器 72 704 字符）→ sanitize 后 216 字符 →
  正文 **0 字符** → `hydrateBody` 抛「抽取结果不比订阅源提供的更多」→ `bodyMissing`。
  ★ 同时修掉同一处的第二个错：自闭合元素（`<svg/>`）的 `outerEnd` 原本留成
  `html.length`，会让 `stripNoise` 从该标签**一直删到文件末尾**。
  ★ 还修掉 `sanitizeHtml` 的一处泄漏：`DROP_CONTENT_TAGS` 的语义是「整棵子树丢掉」，
  但旧实现只对**文本**做了 `insideDropped()` 判断，开标签照写 —— 那 216 字符的产物
  正是 `<a href="…twitter…"><div></a>`。现在丢弃子树里**只入栈、不写出**。
  ★ 为什么以前没拦住：那条「drops nav, header, footer and aside」的夹具用的是
  **不带属性**的 `<nav>` / `<header>` / `<footer>`，正好落在旧公式唯一正确的形状上。
- ★★ **整页没有 `<p>` 的站点（如 `TLDR AI`）完全抽不出正文**（0.12.1）。
  用户报「这个 TLDR AI 为什么订阅不到原文内容」。RSS 里**一个字都没有**，
  真机 `entry.html = 0`、`article.html = 0`。真代码诊断：HTTP 200、79.9 KB 页面，
  `extractMainHtml` 返回 **null**。结构分析：18 个 `<article>` 每个只占全页文本
  0.3–1.1%（过不了语义直取那道 25% 闸门），而**整页 0 个 `<p>`、0 个 `<li>`**
  （Next.js + Tailwind，正文全在 `<div>` 里）⇒ 打分法的**种子集为空** ⇒ 返回 null。
  ★ 关键认识：**种子集为空时放宽阈值是没用的 —— 阈值再松也变不出种子来**，必须
  **换判据**。新增兜底 `pickTextBlock()`：先取「文本最多、链接密度 ≤ 0.25」的
  那一层，再**向下**收敛 —— 子元素仍握着父层 `1 / 1.35` 以上的文本就说明父层只是
  壳，可以继续往下；握不住（父层真装了侧栏/相关阅读）就停。
  ★ 为什么不用「占比 ≥25% 的最内层」：那条硬线上，TLDR 的正文容器占全页 **99.3%**
  而它内部最大的 `<section>` 占 **24.4%** —— 差 0.6 个百分点就会多钻一层。
  ★ 为什么敢放宽判据：它是**严格兜底**，上面任何一条路命中都到不了它 ⇒ 对现有能
  正常抽取的站点**零影响**（`The Rundown AI` / `UCLA` 两个对照组实测逐字节不变）。
- ★★ **模型限流（429）一次就彻底失败，报错还是一串 JSON**（0.12.0）。
  用户报「重新生成译文报错」，原文是
  `model call failed: 429: {"code":429,"message":"Rate Limit Exceeded","type":"openai_rate_limit"}`。
  ★ 查证后的关键事实：**宿主本来就有重试**（`@deepseek-ai/dsh-llm-retry`，默认对
  `RATE_LIMIT` / `SERVER` / `TIMEOUT` / `TRANSPORT` / `EMPTY_RESPONSE` 重试 5 次，
  退避 500ms→10s 带 10% 抖动），但它的文档写明
  「直接走 `ctx.llm.stream()` 的消费方**仍是单次尝试**」—— **本插件走的正是直连 stream，
  落在覆盖范围之外**。所以这不是「忘了写重试」，而是这条路径天生得自己扛
  （在 provider 配置里加 `retryPolicy` 也没用：那条策略的作用域是 agent loop）。
  修法两条：① 按宿主的 `chunk.reason.failure.code` 重试（**不解析 message 字符串**），
  退避与宿主默认对齐，且**只重试快速失败类** —— `QUOTA`（重试变不出额度）与
  插件自己的超时（那意味着已经等很久了）都不重试；
  ② 报错按码说人话（「模型服务限流，已自动重试 4 次仍失败；请稍后重试或在插件设置里换一个模型」），
  并把原始错误附在末尾供排查；认不出的 code **原样透出**，不乱改文案。
- ★★ **译文排版对不上原文**（0.11.0，共同主题都是「HTML → 纯文本这一步有损」）。
  逐条细节见 `CHANGELOG.md`，这里只记判据：
  ① **列表项被劈成「`-` / 空行 / 正文」** —— `<li>` 里包着 `<p>`，而 `<li>` 给 `\n- `、
     `<p>` 给 `\n\n`，标记与正文被空行劈开（真机那篇 36 个列表项 36 个全中）；
  ② **行内格式无声消失** —— `<strong>` / `<em>` / `<code>` 在「剥标签」那一步被吃掉
     （真机全库 493 / 59 / 123 个，一个都没进过译文）；
  ③ **链接退化成纯文本** —— `<a href>` 同样被剥掉（那篇 40 个全丢）。
     修法是让 URL **完全不经过模型**：正文里放 `{{L0}}` 占位符，生成后由
     `restoreLinks` 换回真 URL（模型抄 URL 不可靠，实测把 `q_auto:good` 抄成 `q_2A`）；
  ④ **实体原样进译文** —— 通用路径从不解码，`&amp;` 会字面出现在译文里；
  ⑤ **译文视图里标题出现两次** —— 模型输出的 H1 与界面自己渲染的标题行重复。
  ★ 共同教训：**「排版变了」几乎总是中间那次有损转换造成的**，不是模型不会排版。
  修的时候要一层层量（真 HTML 进、真函数出），别对着截图猜。
- ★★ **「修好了」但用户看不到**（0.10.0–0.10.3 一串，共同主题都是「已生效的东西没被画出来」）。
  逐条细节见 `CHANGELOG.md`，这里只记判据：
  ① 译文**排版被压平、图片全堆文末** —— 正文在进模型之前就被 `htmlToText` 压掉了段落边界，
     而图片判据用整串 URL 精确匹配，模型把 CDN 参数抄错一个字符就全判「缺失」（0.10.0）；
  ② **手动重新生成期间界面一动不动** —— 进度提示只活在「版本缺失」那个分支里，
     一篇两万字的译文要跑约 4 分钟，用户盯着不动的界面只能得出「点了没用」（0.10.1）；
  ③ **菜单项的 `disabled` 没有样式** —— 全插件唯一漏掉的一处，于是禁用项
     `opacity` 还是 1、鼠标还是手型、`hover` 还照样高亮 ⇒「看着能点、点了没反应」（0.10.2）；
  ④ **下拉菜单点外面不关** —— 只有再点一次 ⋯ 才能关（0.10.3）。
  ★ 共同教训：**DOM 状态正确 ≠ 用户看得出**；②③ 都属于「功能明明成功却被判成没生效」，
  只能靠真机量 computed style / 真跑 DOM 事件抓到，读 JSX 读不出来。
- ★★ **整个 DSH 桌面端起不来**（0.6.0 的致命缺陷，0.6.1 修复）。
  `ReaderPage.jsx` 的 CSS 模板串注释里为了点名 `.npr-book-toolbar` 用了**反引号**，
  模板串提前闭合，后面那段被解析成
  「模板串 .npr **减去** book **减去** toolbar」—— 一个**语法完全合法**的表达式。
  于是 esbuild 打包成功、字符串断言全绿、构建守卫也过（它不是语法错误），
  真机上插件一加载就 `ReferenceError: book is not defined`，启动页显示
  `dsh-npie-reader: import failed: book is not defined`。
  ★ 根本教训：**字符串断言答不了「这段代码跑不跑得到」** ——
  659 个用例里浏览器半区**一次都没被执行过**。现在有了（见下方「浏览器半区的产物守卫」）；
- `sanitizeHtml` 丢弃 `<script>` 子树后**吞掉其后全部正文**；
- `isSafeUrl` 的协议白名单可被 ASCII 空白绕过（`java\tscript:`）；
- `parseFeed` 用递归查找读 channel 元数据 ⇒ channel 缺 `<title>` 时**静默取到第一条 item 的标题**；
- `markdownToHtml` 的 `alt` 未做属性转义；
- 个人订阅频道的 key 与查表形状不一致 ⇒ **频道永远显示为空**；
- 新增订阅后视图停在**单个源**上 ⇒ 新订阅的源看不见、上一次订阅的源「消失」，必须回频道列表里点一次；
- 当前频道是**取不到东西的源**时，空列表只说「暂无文章」，不说失败原因、也不给出口；
- 频道 id 已被退订（`localStorage` 里的孤儿 id）时**永久卡在空列表**上；
- 聚合频道的 `total` 恒为 0 ⇒ 客户端的「已有文章就别自动刷」守卫恒不成立，加一个订阅会重抓全部源；
- 条目里 `publishedAt` 存的是 **ISO 字符串**，聚合最新时间时却拿它和数字 `0` 比大小 ⇒ 比较恒为
  false，`newestEntryAt` 永远是 `undefined`，**每个源都显示「还没抓到过内容」** —— 而这个功能
  存在的意义恰恰是防这种事；
- `parseXml` 把「这个地址返回的是网页」和「真的 DTD」报成同一句
  `DTD declarations are rejected` ⇒ 用户会去翻自己源里的 DOCTYPE，而真正该做的是换地址；
- 插件面板铺满主区域却没声明窗口拖动区 ⇒ **打开插件后桌面端窗口拖不动了**；
- **拖动标记一个不少，窗口还是拖不动** —— 因为 `.npr-root` / `.npr-reader` 各带了一个
  `tabIndex={0}`，祖先命中宿主的 `:is(…,[tabindex],…)` no-drag 规则，而 Chromium 是把
  no-drag 矩形从 drag 矩形里**做差**的 ⇒ 两条工具栏的标记被**整块减掉**。
  症状是 grep 全绿、打包与类型检查全过，功能却完全不动（见「边界与已知限制」）；
- 探索页粘贴一个目录里没有的地址只会得到「没有找到匹配的订阅源」⇒ 占位符承诺的
