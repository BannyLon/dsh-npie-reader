# 边界与已知限制

> 哪些做不到、哪些故意不做、哪些已知没解决。

---

## 功能边界（做什么、不做什么）

**订阅侧**自包含，不连接任何远程服务；**书架侧**的书来自**你自己在设置里配的源** ——
本机目录，或你自己的百度网盘（授权由插件内置向导完成，见上方「书源（电子书从哪来）」
与下方「边界与已知限制」）：

- 订阅、阅读数据、译文与改写全部保存在本机 Harness 目录；
- 书架的字节来自本机 HTTP + `Range`，上游是你自己的磁盘或你自己的网盘 ——
  插件不代管账号、不上传任何东西；凭证存在**插件自己的数据目录**里（600 权限），
  落盘只是授权那一次，之后**刷新出来的新 token 只留进程内存**、不回写（见「数据位置」）；
- 网盘书按 **1 MiB 对齐块**取数（只取 pdf.js 真正要的那几段，不是整本下载），
  取到的块**落盘缓存**在数据目录的 `pan-cache/`（上限 1 GiB，超限按「整本书」
  最近使用先删）—— 所以重启 dsh 后再打开同一本书**不再重新取书**，翻过的页秒开。
  阅读进度按书的 id 记在 `data.json`，和缓存无关：就算清空 `pan-cache/`，进度也不丢；
- 本地文件通道自带三道闸（限定目录 + `realpath` + 补分隔符），
  没配任何目录时一本本地书都读不了 —— 详见上方「本地书的读取边界」；
- **朗读 / 导出只送「当前这一节」的纯文本到 TTS 服务**（选本机语音时连这一节都不出本机）：
  点「听本节」不会因为你在读一本书就把整本上传；导出也按**节**做，上限 36 KB ≈ 12000 字，
  整本 19 万字的书会被直接拒绝并说明原因（按字节计费，整本约 ¥28）。念出来的音频缓存在
  本机，同一段文本同一音色只合成一次。
- 不提供**云端**音频转写（0.82.0 起可以在**本机**识别：订阅源自带字幕优先，没有就点「本机识别」，
  引擎与模型下到插件数据目录、音频不出本机；本机识别需要 `ffmpeg` 与约 200 MB 磁盘），
  不提供链接收录，不含视频播放器。

## 已知限制

- **平台链接能解析，但三家给的确定性不一样**（0.84.0 更新口径；0.83.0 曾写下「这三家的链接
  解析没有做」）。**Apple 最稳**：目录 API 直接回 `feedUrl`，只要 collectionId 就够。
  **小宇宙没有公开 RSS**，走的是「读页面标题 → 去 Apple 中国区目录反查」—— 所以**改过名的节目、
  Apple 目录里没有的中文播客会失败**（文案是「没在 Apple 目录里找到这个节目」，不假装订阅成功）；
  这条链路还要抓一次页面，必须带浏览器 UA（裸 `fetch` 实测回 403）。
  **YouTube 订得了，但单集里没有音频文件** —— `feeds/videos.xml` 只给视频页链接，
  所以「识别 / 翻字幕 / 导读」三件事对它都不成立，订阅时就说明。
  任意网页只在它自己声明了 `<link rel="alternate" type="application/rss+xml">` 时才能订，
  没声明就明说没有。
- **有云端识别，但「别人识别过的单集」仍然没有**（0.84.0 更新口径；0.83.0 写的是「没有云端识别」）。
  三档引擎见上表。**共享字幕要一台服务端 + 上传开关**，本插件没有服务端，
  字幕仍只落在本机 `transcripts/`。另：`speech.js` 是**朗读**（文本→mp3）而不是识别
  （音频→文本），别把两者当成一件事。
- **AI 导读有，但覆盖率受字幕与引擎限制**（0.84.0 更新口径）。没有字幕就没有导读 —— 那是
  「先识别」的问题，不是导读的问题；**Qwen3-ASR 不返回时间戳**，30 秒片内按字数比例分配，
  误差可到十几秒（whisper / CrispASR 那条是真时间轴）；长片只按等距抽样读，卡片上标了
  「长片抽样」。
- **Google 翻译在国内是整域不通的，默认会落到模型**（0.84.0 实测）。本机 2026-11-18：
  `translate.googleapis.com` / `translate.google.com` / `clients5.google.com` 直连与系统代理
  全是 `http=000`，Node 侧 `fetch failed`。所以 `auto` 档的实际观感是「先试一下、不通立刻改模型」，
  几秒结束，不会让人干等 N × 12 秒超时；只想用 Google 就把引擎设成 `google`，
  翻不全它会**明确报错**并指路设置项，而不是悄悄给一份半中半英的字幕。

- **本机识别的中文残字与专名错误是「概率问题」，不是 bug**（0.82.0）。实测一集 54 分钟
  （1073 句 / 132 段，base 模型）：**8.8% 的句子里仍夹着繁体字**（「同時」「他沒有拿到簽證」）——
  提示词里的「用简体中文转写」能压下去大部分，压不干净（whisper 的中文分词器本身会在句间漂移；
  改成整段一次识别也不行，那就没有时间轴了）。专名同理：标题里出现过的 `HF0` 能被纠正回来，
  标题里没有的（「孵化器」被听成「复化器」）纠正不回来。要更准就把 `small` 换成
  `large-v3-turbo`（547 MB，慢 2–3 倍）。**这里不假装做二次纠错**：语料级纠错要一整张
  T→S 对照表 + 词典，那是另一个工程，且改错一个词比留一个繁体更难查。
- **本机识别依赖 `ffmpeg`**（0.82.0）。它不随插件提供：macOS 自带的 `afconvert` 只认
  AA/AIFF/CAF/WAV，播客的 mp3/m4a 取不回来；而如果把 ffmpeg 打进插件，包体要从 1.7 MB
  涨到 80 MB 以上。所以缺它就**明说缺什么、怎么装**（`brew install ffmpeg`），不显示按钮。

- **本地书的解析缓存按「体积 + mtime」判新旧，网盘书只能按体积**（0.76.0）。本地文件用
  编辑器改过一章、字数正好没变时，只比体积会**一直读旧正文** —— 而症状是「我明明改了、
  它还念老的」，没人会想到是缓存。网盘拿不到可信的 mtime（三方的 `modified_time` 不可靠，
  且整本才 1 MiB 对齐取块），所以「同名同体积但内容不同」仍是已知边界，这里不假装能修。
  缓存判据收在 `src/host/ebook/store.js` 的 `cacheIsStale()` 一处，宿主与划线重定位共用它
  —— 一边按 mtime 判、一边只按体积判，就会「阅读页是新的、划线还在旧的上面」。
- **定时关闭不跨重启**（0.76.0）。它表达的是「这一次」的意图（今晚再听 30 分钟），存下来
  会让下次打开时莫名其妙地倒计时；换书会清掉已设的定时（换书本来就停播）。
- **订阅侧不连接任何远程服务**：没有云端订阅目录、没有云端译文。译文/改写完全依赖本机模型。
  订阅侧唯一一处主动外发是你自己点「保存并检测」时，插件去探一下你填的那个转 RSS 服务地址 ——
  只发一次请求，只看状态码与内容类型，不登录、不带任何凭据。
- **书架侧只读你自己配的源**（本机目录 / 你自己的网盘），边界要说清楚：
  - **书单由插件自己生成，也由插件自己读**。设置页 → 电子书书架走三步：配源 →
    **每个目录各生成一份书单** → 勾选要**载入**的那几份，产出写在插件数据目录的 `lists/`。
    ★ **生成 ≠ 载入**：扫出来的书单先躺在盘上，没勾上的不进书架 —— 所以「先把源都配好、
    慢慢挑着看」不会让几十个目录的书一次全冒出来。
    ★ 扫描**只产出它拿得到的东西**：`series`（丛书名）/ `year` **刻意留空**，
    因为文件名里的 `[古罗马]` 是**国别**不是丛书，正则猜出来的 `series` 会让「按丛书分组」
    把书归错类，而用户会把这行当成事实 —— 宁可空着。
    你以前那份整理好的 `books.json` 仍然能用：在第三步的「外部书单」里填路径即可，插件不重扫它。
  - **阅读进度存在插件自己的 `data.json` 里，绝不回写外部索引**。首次载入会把你指定的那份
    外部进度（如 `ebook-sorter/data/reading.json`）**只读导入一次**，且**只补插件里还没有的条目** ——
    你在那边读到 125 页，这边不该从第 1 页重来；但这边读得更靠后的进度也不该被那边的旧值盖回去。
  - **凭证由插件自己管**（`pan-app.json` + `pan-token.json`，都在插件数据目录，600 权限）。
    插件不代管账号、不索要密码、不上传任何东西；token 只在授权那一次落盘，
    之后续期出来的新 token 只留进程内存、不回写（见「数据位置」）。
  - **PDF 走原版式，其余走重排**（0.25.0）。98.8% 的书是 PDF，那份「位图 + 文字层 + 缩放 +
    划线锚点」的链路原样不动；EPUB / MOBI / AZW3 / AZW / TXT 另走一条「解析成块模型、按节重排」的路。
    ★ **为什么分成两个组件而不是塞进 `BookReader`**：PDF 阅读器在顶部就有一批 hook、还有一个
    `status === 'unsupported'` 的提前 return，电子书合进去必然打乱 hook 顺序（0.20.6 白屏就是这么来的）；
    而且两者嘴里的「页」不是一回事 —— 一个是缩放后的画布，一个是正文标题块。
  - **一页 = 一个正文标题块，不是 EPUB 的一个 XHTML**（0.25.1）：切页的粒度由**正文里的标题**
    决定，不由文件决定。一个 XHTML 装一整卷的书（《九三年》21 个文件 / 23.9 万字），翻一页就是
    读 1.5 万字，目录里的小节也点不到。宿主侧多一步 `splitByHeadings`（`src/host/ebook/split.js`）
    按 `h1–h6` 再切一层，同一本书变成 103 页。
    ★ **切分以正文标题为准，不以目录为准**：目录会漏条目（这本的 nav 里没有「一、沙丘顶上」），
    正文不会漏自己；★ **块零丢失**是硬不变量 —— 合并后每页的块首尾相接、总数等于切之前
    （4742 块，切前切后一致，测试按数字断）；★ 「只有标题块的页」并进下一张正文页，
    判据是「除标题块外一个正文块都没有」—— 用字数阈值在这一版书上会判反（「第一部 在海上」
    自带一个 11 字的残块，而「第一章 起点 / 第一段。」很短）。
  - **不还原版式，是刻意的边界**：AZW3 / MOBI 里那些首字下沉、图文绕排、浮动图注要还原，
    等于重写一个排版引擎；这次交付的是**文字 + 章节层级 + 可读的外观**。要原版式就转 PDF。
  - **HUFF/CDIC 压缩的 MOBI / AZW3 如实拒绝，不静默出错**：Amazon 自研的 Huffman 字典压缩
    要先把整套 CDIC 解压实现出来，代价远超收益。报错里直接写「用 calibre 转成 EPUB」——
    用户手上有解法，就不该只看到一句「解析失败」。DRM 加密的书同样如实报 `BOOK_DRM`。
  - **电子书正文落盘缓存**（`~/.dsh/storages/dsh-npie-reader/ebooks/<bookId>.json`，带
    `EBOOK_CACHE_VERSION`）：解包 + 解压 + 切块只在第一次做，之后开书是读一个 JSON。
    放宿主而不是渲染进程，是因为**阅读和解读要读同一份解析结果** —— 两边各解一次，
    迟早会因为「哪边先支持了某个边界」而漂移。
  - **伴读带的是当前页的文字：优先 PDF 文本层，没有就用本机 OCR（0.24.7，0.24.8 起自动）**。
    扫描版、纯图片页**没有文字层**，这时打开伴读、在这一页停 700 ms，宿主就用
    macOS Vision 在**本机**认出这一页（**不联网、不花钱**，实测 0.5–0.8 秒/页），
    结果存进 `digests/<bookId>/ocr.json`，下次翻回来直接用 —— **不用点任何按钮**。
    ★ **顺序不能反**：文字层逐字精确（连标点、脚注编号都对），OCR 一定有个别错字，
    所以有文字层时 OCR 结果**永远不会**顶掉它；面板也会明说这一页是「本机识别」。
    ★ **只认你停下来的那一页**，不做整本：整本 400 页约 5 分钟、全库 2370 本约 197 小时
    —— 按需是唯一合理的形态。翻页途中经过的页不会跑（700 ms 防抖），每页只自动试一次；
    失败之后面板会留一个「识别这一页的文字」按钮，那一次会**如实报错**。
    ★ 识别不出来（纯图片页）时面板**明说**，而不是拿书名猜内容 —— 一个建立在缺失
    数据上的、听起来很确定的回答，比「我看不到」危险得多。
    跨页提问、全书检索也不在范围内：这是「陪你把这一页读懂」，不是「替你读完这本书」。
  - **电子书不走 OCR**（0.25.0）：解析出来的每一节都有字，所以「没文字层就 OCR」那条补救
    路径对 EPUB / MOBI / AZW3 / TXT 不生效 —— 它们真正会缺的是**图**（见「只做文字」那条）。
    另外 `digestOutline` 把**不足 1500 字**的节并进相邻章，免得为扉页、版权页、三行题记
    各花一次模型调用（一整本只有一章时才不合并，因为那时没得并）。
  - **「整本书翻译」曾经不做，0.59.0 / 0.60.0 起做了**。2026-10-24 那条结论是「别加」，
    判据是「书架实测 2637 本里 2619 本（99.3%）**书名**是中文，把中文书再译一遍是
    伪需求」。这个统计没错，但它数的是**书名的语言**，而决定要不要译的是**正文的语言** ——
    在读的那几本英文 EPUB（`brontë-wuthering-heights`…）标题是拉丁字母、正文也是英文，
    正是当初没被计进去的那一小撮。★ 口径最后落在**按书判**：助手只列「在读」里正文是
    外文的电子书，中文书不占一行，连宿主 `start` 都会拒。★ 这里的判据修过一次
    （0.61.0 → 0.62.0），记下来免得再走一遍：**`total === 0`（有几节可翻）不等于
    「中文书」** —— 「可翻块」是逐块判的，中文段落里夹一串英文人名就会被判成该翻，
    书名是拼音的那些（`KuaYueHongGou-DianFuXing` 就是一本**中文**书）尤其容易骗过人。
    真判据是**整本正文的汉字占比 ≥ 0.7**（`bookScript`，按字符量加权、不按节投票）。
    仍然**不做**的两件：不做**全库**整本翻译
    （2600+ 本 × 几十分钟），也不给 **PDF** 做（没有块模型，译文贴不回原位）。
    ★ 订阅那一侧照旧是译文与改写（0.13.0）：14 个源里 10 个是英文。
  - **书单路径必然会变**（换机器、挪目录），所以**每条书源**都是一条设置项
    （设置页 → 电子书书架），界面会把每份书单**解析后的绝对路径**显示出来。少了这一句，
    「以为在读书单、其实在读空气」会悄悄发生 —— 而且看起来一切正常。
  - **书架路由自带信任栅栏**。宿主对插件路由的派发是「先精确路由、再走鉴权拦截器」，
    **命中插件路由的请求不经过宿主的 token 鉴权**，所以每条路由的安全由它自己负责。
    三条判据：socket 对端必须是回环、`Host` 头必须解析成回环主机名、
    显式拒 `sec-fetch-site: cross-site`。★ 关键是第二条：恶意网页可以把域名解析到
    `127.0.0.1`（DNS rebinding），此时请求确实打到了本机，而 `Origin` 与 `Host`
    **都是攻击者的域名**、浏览器视为同源 —— 只看这两个相等**挡不住**它。
    `X-Forwarded-For` 一律不信（既不能否决、也不能授予信任）。
  - **外抓原文页有私网守卫（SSRF），但只守在「第三方可控的地址」上**。`hydrateBody` 抓的
    `entry.url` 是 **feed 内容给的**：恶意 feed 只要把条目的 `<link>` 写成
    `http://127.0.0.1:<端口>/…`，插件就会替它读本机服务 —— 而上面那道栅栏恰好信任
    「来自回环 socket 的请求」，所以这一跳能绕过去。三条判据（`src/host/net-guard.js`）：
    协议只收 `http/https`；`localhost` / `*.localhost` / `*.local` / `*.internal` / 裸 IP
    不用查 DNS 就拒；域名必须解析，**任一**记录落在私网段就拒（只看第一条会被
    「公网 A 记录 + 私网 A 记录」的混合域名绕过）。解析失败一律**拒绝**（fail-closed）：
    宁可这次读不到原文，也不要在解析器被投毒时放行。
    - 私网段**不止** RFC1918：`127/8`（不止 `.0.1`）、`169.254/16`（**云元数据
      `169.254.169.254` 就在这段**，SSRF 最经典的靶子）、`100.64/10`（CGNAT）、`0/8`、
      `198.18/15`、三段 TEST-NET、`192.0.0/24`、`224/4` 与 `240/4` 都算。
      IPv6 不靠字符串前缀判：先解析成 8 个 hextet 再按位比，所以 `::ffff:127.0.0.1`、
      `fe80::1%en0`、`2001:0db8::`、`64:ff9b::/96` 都拦得住。
    - ★ **订阅地址不设限**：你在设置里手填的 feed 地址、转 RSS 服务基地址（wewe-rss
      这类服务本来就常跑在 `localhost:4000`）**必须**能连。守卫只接在抓原文页那一条路上。
    - ★ **重定向必须逐跳校验**：`redirect: 'follow'` 会让「公网地址 302 到 127.0.0.1」
      发生在 fetch 内部，前置校验根本看不见。所以是 `redirect: 'manual'` + 每跳重新校验
      + 跳数上限 5。守卫接在 fetch **之前**（接在后面只是事后报错，内网服务已经被打过一次）。
    - **残余风险（写在明面上）**：DNS 解析与实际连接之间仍有 TOCTOU 窗口 ——
      解析时是公网、连接时变成 `127.0.0.1`。要彻底关掉得自己建 socket 连解析出的 IP，
      `fetch` 做不到。重定向那一半已经堵住，剩下的窗口需要攻击者同时控制 DNS 的 TTL
      与响应时序。

  点「重新生成」后才换。这是用户明确的选择（「等我手动重生成」）。
- **英文自动翻译是计费行为，所以默认关闭**：打开后每打开一篇**还没有中文版本**的英文原文
  就调一次翻译模型。中文原文、日文/韩文原文、语种样本不足（少于 60 个有效字符）
  都不会触发；已经有中文版本的也不会重翻。翻译期间阅读区有状态提示，并带一个
  「以后不自动翻译」的出口。想临时看某一篇的译文，也可以在阅读区点「生成」。
- **限流与 5xx 会自动重试，但 `Retry-After` 用不上**。要说清楚三件事：
  - **重试会重复计费**：每一次尝试都是一次真实的模型请求。次数上限 5 次，
    退避 500ms→10s 带 10% 抖动（与宿主默认对齐），整条链另有 `timeoutMs + 5 分钟` 的总预算。
  - **两类失败刻意不重试**：`QUOTA`（配额用尽 —— 重试变不出额度，只会让你白等），
    以及**插件自己的超时**（整体上限 / 静默看门狗 —— 那意味着「已经等很久了」，
    再等一遍只是让你多等一遍）。用户取消之后一个字都不会再发。
  - ★ **宿主能用 `Retry-After`，插件不能**：`chunk.reason.failure` 里只有
    `{ message, code }`，没有 headers、没有 status。宿主 `llm-retry` 在 agent loop 侧
    可以拿它替换本地退避，直连 stream 的插件侧拿不到 —— 写「读 `Retry-After`」
    只会得到一个永远 `undefined` 的死分支，所以**没写**。
- **翻译用的模型可以单独指定**（设置 → 阅读体验 → 「翻译 / 改写用哪个模型」），
  留空即跟随 Harness 默认模型。几点要说清楚：
  - 取值按**第一个** `/` 切（`<provider>/<model>`），所以模型 id 自己带斜杠也没问题
    （`openrouter/anthropic/claude-sonnet-4`）。
  - **取值读不出来时是报错，不是静默回退**。静默回退的症状是「你以为在用免费模型，
    其实一直在花默认模型的钱」，没有任何提示，只有账单能看出来。
  - 阅读区那两处字样（自动翻译的状态条、「生成」按钮）显示的是**这次实际会用的那个
    模型名**（`provider · model`），不是「Harness 默认模型」四个字 —— 指定了模型就
    显示它，留空才显示默认的那个（连同名字）。名字由宿主给出，与生成路径**同一份判据**；
    拿不到具体名字时退回**不含模型名**的说法，绝不编一个出来。
  - 下拉框里如果看不到某个 provider，先去 Harness 的「设置 → 模型」里把它配好
    （「添加模型提供商」→「自定义模型 API」）；插件只列出 Harness 已注册的东西。

  ```
  html[data-platform=darwin] :is(button,a,input,select,textarea,summary,
    [contenteditable=true],[tabindex],[role=dialog],[role=menu],…){-webkit-app-region:no-drag}
  ```

    它**不会**在后台偷偷开始 —— 必须点「生成解读」。
  - **DOCX 仍不支持**：书架里仍列出来并标「暂不支持」（0.25.0 打开了 EPUB / MOBI / AZW3 /
    AZW / TXT，DOCX 不在这一轮里）。
  - **电子书只做文字，不做图片**：插图、封面、表格边框都在解析时丢掉。图注的文字通常还留着，
    但「这张图长什么样」这个信息没了 —— 图多的书（画册、图解类）请走 PDF。
  - **导出的 skill 包里没有原文**（0.20.0）：只有解读。原文留在插件的 `text/chNN.txt` 里，
    想让它跟着包走需要自己拷 —— 这也意味着这个包不能替代读原文，它是「先问哪儿值得看」的索引。
  - **书型是猜的，且只按密度猜**：代码特征 / 引号密度能分开「技术书 / 小说 / 其它」，
    分不开「技术书里的访谈」与「小说里的代码清单」。依据会写进 `SKILL.md`，
    猜错时在面板里显式选一次就行（`technical` / `fiction` / `nonfiction`）。
  - **导出包不会自动被任何 agent 用上**：它是一个普通目录，界面只把绝对路径显示出来。
    这是刻意的 —— 往 `~/.claude/skills` 之类的位置写属于「用户机器上的别的东西」。
